deepseek harness笔记1

本文重新组织论文A Programming Paradigm for Spatiotemporal Composability的第3章和第4章, 并以插件运行时Cordis及其在dsh中的使用为背景. 这不是翻译: 定义和定理的形状按本文的需要重新安排, 论文的说法只在对照时提到. 目标是验证插件的生命周期性质, 插件的业务逻辑不在范围之内.

重构遵循以下几条原则.

  1. 论文和Cordis都不是权威. 每个设计点都选合理, 直接, 简单的方案; Cordis的做法若体现了局部的最佳实践就跟着它.
  2. 所有跨组件共享的可变状态都是某个服务的状态, 不设另外的环境部分.
  3. 程序是归纳类型, 看不到状态, 只能通过操作的结果决定下一步. 所以组件只碰自己声明过的东西, 这是由构造保证的.
  4. 服务状态从一开始就配备等价关系≃, 控制部分 (生命周期, 名字, 绑定的身份) 用严格相等.
  5. 定理的最终形状是: 若每个服务满足它的规格, 每个插件满足它的义务, 则整个系统满足生命周期性质.

第1章讲效应怎样撤销, 第2章到第5章讲组件怎样通过服务相互依赖, 第6章到第9章给出生命周期演算及其元理论, 第10章逐条对照论文.

第1章 可撤销效应

这一章对应论文的3.1节. 本章用严格相等和全函数, 与论文的陈述一致. 出发点是: 插件卸载时, 它对共享状态做过的每件事都必须撤掉, 所以每个效应都要带着它的逆. 下面固定一个类型Γ, 作为世界的状态, 并记End⁡(Γ)≔Γ→Γ.

第1.1节 效应上下文

定义1.1.1. 定义TΓ≔End⁡(Γ)×End⁡(Γ), 其中的元素(f,g)由前进函数f和撤销函数g组成. 复合定义为 ( f1 , g1 ) ∘ ( f2 , g2 ) ≔ ( f1 ∘ f2 , g2 ∘ g1 ) . 前进部分按通常的顺序复合, 撤销部分倒过来: 后做的事先撤.
命题1.1.2. TΓ在上述复合下是幺半群, 单位元是(id,id).
定义1.1.3. 定义效应上下文∂⁡Γ≔Γ×End⁡(Γ). 其中的元素(γ,φ)由当前状态γ和累加器φ组成, φ的用意是把一切撤回到起点. 定义track:TΓ→End⁡(∂⁡Γ)为 track⁡ ( f,g ) ⁡ ( γ,φ ) ≔ ( f⁡ (γ) , φ∘g ) , 定义recover:End⁡(∂⁡Γ)为 recover⁡ ( γ,φ ) ≔ ( φ⁡ (γ) ,id ) . track在前进的同时把g接到累加器的内侧, recover一次用掉累加器.
命题1.1.4. track是幺半群同态, 并且pr1∘track⁡(f,g)=f∘pr1.
定理1.1.5. 若g⁡(f⁡(γ))=γ, 则recover⁡(track⁡(f,g)⁡(γ,φ))=recover⁡(γ,φ). 特别地, 若g∘f=id, 则recover∘track⁡(f,g)=recover.
证明. 直接计算: recover⁡ ( track⁡ ( f,g ) ⁡ ( γ,φ ) ) = recover⁡ ( f⁡ (γ) , φ∘g ) = ( φ⁡ ( g⁡ ( f⁡ (γ) ) ) ,id ) = ( φ⁡ (γ) ,id ) = recover⁡ ( γ,φ ) 第三个等号用到了前提. 若g∘f=id, 则前提对每个γ都成立.

第1.3节 效应的独立性

LIFO总是可行的, 但组件的卸载顺序由系统决定, 不一定是加载顺序的逆. 要按别的顺序撤销, 效应之间必须互不干扰.

定义1.3.1. 对于e∈EΓ, 定义生成元集合 G⁡ (e) ≔ { pr1 ∘e } ∪ { pr2 ⁡ ( e⁡ (γ) ) | γ∈Γ } , 以及变换幺半群M⁡(e)≔⟨G⁡(e)⟩, 即End⁡(Γ)中由G⁡(e)生成的子幺半群. 对(f,g)∈TΓ有G⁡(⌜f,g⌝)={f,g}.
引理1.3.2.
  1. 对S,T⊆End⁡(Γ), 若∀a∈S.∀b∈T.a∘b=b∘a, 则∀a∈⟨S⟩.∀b∈⟨T⟩.a∘b=b∘a;
  2. M⁡(e1⋄e2)⊆⟨G⁡(e1)∪G⁡(e2)⟩.
这是论文的引理18.
证明. (1) 对固定的b, 与b交换的元素之集合包含id且对复合封闭, 是一个子幺半群. 所以若它包含一个生成元集合, 就包含其生成的子幺半群. 把这个论证对两边各用一次即可. (2) pr1∘(e1⋄e2)等于pr1∘e1与pr1∘e2的复合; e1⋄e2在γ处给出的逆是e2在γ处和e1在某点处给出的逆的复合. 所以e1⋄e2的生成元都落在右边的子幺半群里, 由它们生成的M⁡(e1⋄e2)也是.
◻
定义1.3.3. e1和e2独立, 如果
  1. M⁡(e1)与M⁡(e2)的元素两两交换;
  2. 对每个h∈M⁡(e2)和γ, pr2⁡(e1⁡(h⁡(γ)))=pr2⁡(e1⁡(γ)), 即e2的变换不改变e1给出的逆; 反之亦然.
对⌜f1,g1⌝和⌜f2,g2⌝, 第一条就是四对函数两两交换, 第二条自动成立. 这是论文的定义19.

证明. 对i归纳. i=j时, γj=fj⁡(γj−1)是定义, gj⁡(γj)=γj−1是ej的见证条件. 归纳步: γ i+1 = f i+1 ⁡ ( fj ⁡ ( γi′ ) ) = fj ⁡ ( f i+1 ⁡ ( γi′ ) ) = fj ⁡ ( γ i+1 ′ ) 第二个等号用到fi+1∈M⁡(ei+1)与fj∈M⁡(ej)交换; 同理, gj∈M⁡(ej)与fi+1交换给出第二式. 至于逆不变: gi = pr2 ⁡ ( ei ⁡ ( γ i−1 ) ) = pr2 ⁡ ( ei ⁡ ( fj ⁡ ( γ i−1 ′ ) ) ) = pr2 ⁡ ( ei ⁡ ( γ i−1 ′ ) ) 最后一步正是独立性的第二条, 取h=fj∈M⁡(ej).

第2章 在等价意义下, 部分地读

论文3.3.2节指出, 3.1节中的恢复到原状态是理想化的: free不会恢复malloc之前的堆布局, 被撤销的新鲜名字下次也不会再用. 所以等式都要读成某个等价关系. 另外, set这类操作带有前条件, 效应函数应该是部分的. 这一章把两件事一起做.

定义2.1. 设Γ带有等价关系≈. 定义 PEffΓ ≔ Γ→ Maybe ( Γ× End⁡ (Γ) ) . 两个结果相关, 当且仅当都是None, 或者状态相关且逆逐点相关. 一个映射g尊重≈, 当且仅当x≈y⇒g⁡(x)≈g⁡(y).
定义2.2. e∈PEffΓ带见证, 当且仅当
  1. 若e⁡(γ)=(δ,g), 则g⁡(δ)≈γ;
  2. 上述g尊重≈;
  3. e本身尊重≈: 相关的输入给出相关的结果.
这是论文定义37在Maybe中的读法.
定义2.3. 部分的⋄与全函数版本相同, 只是任一步为None时结果为None. 对a:Γ→Maybe(Γ×End⁡(Γ)×B)和κ:B→PEffΓ, 按结果绑定为 bind⁡ ( a,κ ) ⁡ (γ) ≔ let ( δ,g,b ) ≔ a⁡ (γ) in let ( ε,h ) ≔ κ⁡ ( b⁡ (δ) ) in ( ε, g∘h ) . 这是论文的式(36): 每一段执行一个操作, 再根据结果选择后续.
定理2.4. 若e1, e2带见证, 则e1⋄e2带见证; 若a的前两个分量带见证, a在相关的输入上给出相同的结果b, 且每个κ⁡(b)带见证, 则bind⁡(a,κ)带见证. 取≈为相等且效应为全函数时, 定义2.2恰好退回EΓ⁎.
证明. 与全函数的情形相同, 只是每一处等式换成≈. 见证条件: 若e2⁡(γ)=(δ,s), e1⁡(δ)=(ε,t), 则s⁡(t⁡(ε))≈s⁡(δ)≈γ, 第一步要求s尊重≈, 这正是定义中的第二条. 复合的逆是尊重≈的映射的复合, 仍然尊重≈; 复合本身尊重≈是因为相关的输入在每一段都给出相关的结果. 按结果绑定时, 相关的输入给出相同的结果, 所以选择的是同一个后续, 论证不变.

论文的引理38断言3.1节的全部等式都可以读到≈下. 这里只给出演算用得到的部分 (上面两条封闭性). 定理20和推论21的≈版本本文不讨论: 演算的恢复和合流不经过它们, 而是直接以操作级的假设证明.

第3章 服务

论文的定义24把键k上的余效应定义为三元组, 包含值类型, 等价关系和操作集合. 我们把它整理成一个记录, 称为服务.

定义3.1. 一个服务Σ由以下资料组成: 状态类型S, 其上的等价关系≃, 操作类型Op (参数已经放进操作里), 结果类型Out, 以及 run: Op→Tok→S→ Maybe ( S× End⁡ (S) ×Out ) . 其中Tok=ℕ是运行时交给这次操作的新鲜令牌, 用于事件钩子这类生成出来的身份 (JS中由对象身份充当).

与论文相比有两处不同. 第一, 多了令牌参数. 第二, 全系统只有一个服务Σ, 不是每个键一个; 需要多种服务时先取它们的和, 这样避开了依赖类型的映射. 除去Maybe和令牌, 操作的形状S→S×End⁡(S)×Out与论文的式(22)相同: 前两个分量是值上的效应函数, 第三个分量是结果. 结果是程序获得信息的唯一途径, 也是观察者区分状态的依据, 见第4章.

定义3.2. 操作a在令牌t下良好, 当且仅当
  1. 带见证: 若runats=(s′,g,o), 则g⁡(s′)≃s;
  2. 尊重≃: 若s1≃s2, 则runats1与runats2都是None, 或分别是(s1′,g1,o)和(s2′,g2,o), 其中s1′≃s2′且∀x.g1⁡(x)≃g2⁡(x);
  3. 给出的逆尊重≃: 若runats=(s′,g,o), 则∀x,y.x≃y⇒g⁡(x)≃g⁡(y).
定义3.3. 称(a,ta)对(b,tb)撤销独立, 如果对a可能给出的每个逆g
  1. 对每个x, runbtbx与runbtbg⁡(x)都是None; 或者runbtbx=(x1,h1,o), runbtbg⁡(x)=(x2,h2,o), 其中x2≃g⁡(x1)且∀y.h2⁡(y)≃h1⁡(y);
  2. 对b可能给出的每个逆h, ∀x.g⁡(h⁡(x))≃h⁡(g⁡(x)).
第一条说b不在乎a的效应是否已被撤掉, 第二条说两者的逆可以交换. 称它们可交换, 如果对每个s, 先a后b与先b后a都失败, 或都成功并给出≃相关的终态, 且a和b各自的结果相同.

撤销独立正是撤掉a的效应而让b的效应留着所需要的条件; 它不要求a和b的前进函数交换. 恢复精确性只需要撤销独立, 合流还需要可交换.

定理3.4. 设a带见证且runats0=(s1,g,o). 设τ是一串他人的步骤 (他人的操作, 以及他人的逆), 每一步都与g相容 (即满足定义3.3中相应的一条), 记exec⁡(τ,s)为从s出发执行τ所到达的状态. 那么 g⁡ ( exec⁡ ( τ, s1 ) ) ≃ exec⁡ ( τ, s0 ) , 并且τ中他人的操作在两次执行中得到相同的结果. 换言之, 在终点撤销a, 等于a从来没有执行过.
证明. 记实际执行的状态为x, 不执行a的执行的状态为y, 对步骤归纳证明g⁡(x)≃y并且两边他人的操作看到相同的结果. 起点处g⁡(s1)≃s0是a的见证条件. 对他人的操作b: 相容性说b在x和g⁡(x)上同时失败或同时成功, 后者的后继≃前者的后继再施g, 结果相同; 再由b尊重≃, 把g⁡(x)换成y也一样. 对他人的逆h: g⁡(h⁡(x))≃h⁡(g⁡(x))≃h⁡(y), 第一步是相容性, 第二步是h尊重≃.
◻
例子3.5. 按名字索引的注册表 (如ctx.tools): 状态是名字到可选值的映射, 逐点比较. Register⁡(x,v)在x已被占用时失败, 逆是删去x; Lookup⁡(x)读出x处的值, 逆是恒等. 每个操作都良好. 名字不同的登记, 以及不会遇到同名登记的查询, 满足合流所需的全部假设.
例子3.6. 有序事件总线 (如ctx.on): 状态是带令牌的钩子列表. 两次注册不可交换; 按回调注销 (Cordis的旧做法) 也不是精确的逆. 若启动模型中没有分发操作, 并且忽略顺序 (比较多重集), 监听器注册满足全部假设.

第4章 观察等价

服务的≃应该取什么? 论文的回答是: 观察者只能运行操作并读取结果, 两个状态相关当且仅当没有观察者能区分它们.

定义4.1. 一个测试是字母的有限序列. 字母或者是LF⁡(a,t), 运行操作并记录结果 (操作失败则整个测试无定义); 或者是LI⁡(g), 施加某个操作可能给出的逆g. 记runTest⁡(w,s)为测试w在s上记录的结果序列 (无定义时为None). 定义不可区分 s∼ s′ :⇔ ∀w. runTest⁡ ( w,s ) = runTest⁡ ( w, s′ ) . 一个等价关系R可容许, 当且仅当每个操作都尊重它 (即R⁡(s,s′)时, runats与runats′同为None, 或给出R相关的后继和相同的结果), 并且每个可能给出的逆g都满足R⁡(x,y)⇒R⁡(g⁡(x),g⁡(y)).
定理4.2. ∼是可容许的, 并且对每个可容许的R有R⊆∼. 换言之, ∼是操作所尊重的最粗的等价关系. 特别地, 操作良好的服务有≃⊆∼.
证明. 可容许: 设s与s′不可区分. 只有一个字母LF⁡(a,t)的测试说明a在两者上同时失败或同时成功, 且结果相同; 在一个测试前面加上这个字母仍是测试, 所以两个后继也不可区分. 逆字母同理. 包含: 设R可容许, R⁡(s,s′). 对测试的长度归纳: 每个字母都把R相关的状态送到R相关的状态, 并给出相同的结果, 所以整个测试在两边的结果相同.
◻

这就是最大互模拟: 测试每走一个字母, 两边同时走一步, 比较定义性与结果.

定理4.3. 在带分发的有序事件总线上, 设c1≠c2是两个回调, 分别用令牌t1≠t2注册; 从同一状态出发, 记s12为先注册c1再注册c2所得的状态, s21为相反顺序所得的状态. 则对每个可容许的R, ¬R⁡(s12,s21). 换言之, 不论取哪个可容许的等价关系, 两次注册都不可交换.
证明. 设两种顺序得到的状态被某个可容许的等价关系联系起来. 由上一个定理, 它们不可区分. 但只含一个分发字母的测试按注册顺序返回回调的列表, 两种顺序给出的列表不同, 矛盾.
◻

分发会暴露注册的顺序. 所以例子3.6中把分发排除在启动模型之外是被迫的, 而不是随意的选择.

第5章 程序及其解释

论文的定义41把组件的效应函数刻画为: 每一段执行一个操作, 再根据结果选择后续. 我们把这个闭包直接做成一个归纳类型, 并把它解释回第2章的部分效应.

定义5.1. 程序由以下文法生成: P⩴ Done|Fail| Op⁡ ( k,a,κ ) | Provide⁡ ( k,s,P ) | Spawn⁡ ( c,P ) , 其中κ:Out→Prog. Op⁡(k,a,κ)在键k的服务状态上执行a, 把结果交给κ; Provide⁡(k,s,P)以初始状态s提供键k; Spawn⁡(c,P)注册子组件c.

这就是一个free monad, κ是续延. 程序是良基的 (每条路径都有限, 但κ可以无穷分叉, 所以路径长度未必有界), 看不到状态, 能得到的信息只有操作的结果. 名字和provision编号由规则层分配, 程序不接触.

定义5.2. 存储是Store≔K⇀S, 两个存储相关当且仅当定义域相同且逐键≃ (论文的定义33). 定义 set⁡ ( k,s ) ⁡ (σ) ≔ { ( σ [ k↦s ] , λ σ′ . σ′ ∖k ) , 若 k∉ dom⁡ (σ) None , 否则 ( liftk at ) ⁡ (σ) ≔ let ( s′ ,g,o ) ≔ runat σ⁡ (k) in ( σ [ k↦ s′ ] , λ σ′ . σ′ [ k↦ g⁡ ( σ′ ⁡ (k) ) ] ,o ) 后者在k∉dom⁡(σ)或run失败时为None. 提升后的逆在k∉dom⁡(σ′)时保持σ′不变, 所以它是全函数. 第一个是论文定义23的set, 第二个是式(23)的提升. 提升后的逆作用在撤销时的存储上, 只改动键k, 所以别的组件在中间做过的事会保留下来.
定义5.3. 程序的解释⟦P⟧t:PEffStore (t是起始令牌) 定义为 ⟦Done⟧ t = η ⟦Fail⟧ t = λσ.None ⟦ Op⁡ ( k,a,κ ) ⟧ t = bind⁡ ( liftk at , λo. ⟦ κ⁡ (o) ⟧ t+1 ) ⟦ Provide⁡ ( k,s,P ) ⟧ t = ⟦P⟧ t+1 ⋄ set⁡ ( k,s ) ⟦ Spawn⁡ ( c,P ) ⟧ t = ⟦P⟧ t+1 spawn不是存储上的效应, 所以解释为恒等.
定理5.4. 若服务的操作都良好, 则每个程序的解释都是带见证的部分效应; 特别地, ⟦P⟧ t ⁡ (σ) = ( σ′ ,g ) ⇒ g⁡ ( σ′ ) ≃σ . 换言之, 一个组件单独卸载时, 存储在≃意义下复原.
证明. 对P的结构归纳. Done和Fail的情形是平凡的. set⁡(k,s)带见证: 在k∉dom⁡(σ)时, (σ[k↦s])∖k=σ; 它的逆尊重存储的等价, 因为存储是逐键比较的. liftkat带见证: 它的逆只改动键k, 在该键上就是操作a的逆, 由a良好即得. 于是Op的情形由按结果绑定的封闭性得到, Provide的情形由⋄的封闭性得到, Spawn的情形就是归纳假设.
◻
定理5.5. 解释与演算的步骤一致: 一个操作步或provide步恰好是解释的一段, 它的撤销项施加这一段的逆. 特别地, 设组件c的fiber从存储σ出发单独 (没有其他fiber走步) 加载到Active, 开始时计数器为t, 则⟦body⁡(c)⟧t⁡(σ)=(σ′,g)有定义, 结束时的存储≃σ′, 并且它累加器中新增的撤销项按LIFO复合起来逐点≃g.
定义5.6. 独立性在Maybe中的读法: 两个部分效应 (或两个操作在各自令牌下) 独立, 如果它们的生成元在部分函数的意义下两两交换, 并且一方的生成元既不改变另一方的定义域, 也不扰动另一方给出的逆和结果. 只在生成元上要求. 用于操作时, 这就是论文的定义39(键可交换)的读法.
定理5.7. 若k≠k′, 则liftkata与liftk′btb在定义5.6的意义下独立. 这是论文的定理40.
证明. liftkat的前进函数和它给出的逆都只读写键k, 其余键原样保留. 两个分别只读写k和k′的映射, 在k≠k′时逐点交换, 再由第1章中的引理, 生成的子幺半群也交换. 另外, 操作在σ处是否有定义, 给出的逆和结果都只依赖于σ⁡(k), 而另一方的生成元不改变它.
◻
定理5.8. 定义39蕴涵撤销独立和可交换; 因此论文自己的假设推出合流所需的服务假设 (见定理9.5.5), 以及恢复精确性所需的假设 (见定理9.3.2).

反过来不成立: 演算要求得更少, 只对两个fiber可能在同一个键上相遇的操作对, 并且只在令牌不同时要求. 论文的定理42(相遇处键可交换则效应独立)因此不必经过效应函数的独立性, 而是直接推出了演算的操作级假设.

第6章 组件, fiber与状态

从这里开始对应论文的第4章. 论文的演算先假设迁移是原子的, 瞬时的, 不会失败的 (4.2节), 再在4.3节逐一去掉这些假设. 我们直接给出去掉之后的版本: 每个服务操作是一个原子步, 步与步之间都可以放弃.

定义6.1. 一个组件是四元组 ⟨ d⊆K , p⊆K , body∈Prog ,reacts ⟩ , 分别是依赖, 可能提供的键, 启动程序, 以及事件处理器 (组件编号的列表). 组件放在状态之外的程序表prog:C→Component里.
定义6.2. 组件的义务 (静态, 可机械检查): body中每个Op⁡(k,a,κ)满足k∈d∪p, 每个Provide⁡(k,s,P)满足k∈p.

与Cordis不同, 提供的键是静态声明的. 这使得不同fiber的p两两不相交可以在插入时检查, 依赖关系是否无环也可以静态判定; 进展和合流都需要无环.

定义6.3. 状态是⟨next,F,B⟩, 其中next是新鲜名字, provision编号和令牌共用的计数器, F:ℕ⇀Fiber是注册表, B:K⇀Binding是当前的服务绑定: Fiber ⩴ ⟨ c∈C , π∈ ℕ+ {root} , τ∈𝔹 , θ∈Θ ⟩ Binding ⩴ ⟨ pid,owner, s∈S ⟩ θ ⩴ Inactive⁡ (ζ) | Loading⁡ ( P,acc,ω ) | Active⁡ ( acc,ω ) | Unloading⁡ ( acc,ω,ζ ) u ⩴ UOp⁡ ( k,pid,tok,g ) | UProv⁡ ( k,pid ) | USpawn⁡ (m) 这里π是父fiber, τ是已请求移除标记, ζ是可选的错误 (ζ=⊥表示没有错误, 非⊥的错误记作ξ), 累加器acc是撤销项u的列表, 表头是最近的一项; ω:K⇀ℕ是视图, 定义域恰为该fiber的组件的d, 记录每个依赖解析到的provision编号.

几点说明.

  • 四个生命周期状态代替Cordis的六个: FAILED就是Inactive⁡(ξ), DISPOSED就是条目不存在.
  • 累加器就是第1章的φ, 只是拆成撤销项的列表, 以便逐项撤销, 逐项设守卫. UOp项记下操作用的令牌, 这是恢复精确性的证明所需要的.
  • 以provision编号作为提供的身份. 提供者撤掉再重新提供时编号改变, 依赖它的fiber会重新加载, 绝不会拿着过期的绑定继续运行.
  • 绑定中的服务状态被提供者和所有依赖者共同操作, 是共享且可变的.

第8章 规则

规则写作γ⟶ℓγ′, 标签ℓ决定唯一的后继 (若存在), 所以演算就是一个确定性的函数step:State→Label→MaybeState. 选择哪个标签是调度的事, 不在演算之内. 凡是从next取名字, 编号或令牌的规则, 都随后把next加一.

第8.1节 编排规则

编排规则是外部输入.

  • O-Insertc: 若p⁡(c)与所有现存fiber的p不相交, 则以m≔next为名插入⟨c,root,false,Inactive⁡(⊥)⟩, next加一.
  • O-Disposen: 若n∈dom⁡(F), 则τn≔true.
  • O-Resetn: 若θn=Inactive⁡(ξ), 则θn≔Inactive⁡(⊥).
  • O-Restartn: 若θn为Loading⁡(_,acc,ω)或Active⁡(acc,ω), 且¬τn, 则θn≔Unloading⁡(acc,ω,⊥).
  • O-Reactni: 若θn=Active⁡(acc,ω), ¬τn, reacts⁡(cn)的第i项为c, 且p⁡(c)不冲突, 则插入子fiber⟨c,n,false,Inactive⁡(⊥)⟩, 名为m≔next, 并令θn≔Active⁡(USpawn⁡(m)::acc,ω).

O-Reset对应Cordis在失败后用update重试; O-Restart对应restart, 卸载后由L-Begin重新加载; O-React把一次事件反应建模为子fiber, 反应的操作就是子fiber的操作, 构成一个运行期效应, 单独撤销就是对子fiber执行O-Dispose.

第8.2节 加载

  • L-Beginn: 若θn=Inactive⁡(⊥)且target⁡(n)=ω≠⊥, 则θn≔Loading⁡(body⁡(cn),[],ω).
  • L-Divertn: 若θn=Loading⁡(P,acc,ω)且target⁡(n)≠ω, 则θn≔Unloading⁡(acc,ω,⊥).
  • L-Stepn: 若θn=Loading⁡(P,acc,ω)且target⁡(n)=ω, 则按P分情况:
    • Done: θn≔Active⁡(acc,ω);
    • Fail: θn≔Unloading⁡(acc,ω,EUser);
    • Op⁡(k,a,κ): 依赖键查视图ω, 自己提供的键查B (owner必须是n), 得到编号p; 取令牌t≔next, 在该绑定的状态s上运行runats. 失败则进入Unloading并带错误; 成功得到(s′,g,o)时写回s′, 并令θn≔Loading⁡(κ⁡(o),UOp⁡(k,p,t,g)::acc,ω). 解析失败视为失败;
    • Provide⁡(k,s,P′): 要求k∈p⁡(cn)且B⁡(k)未定义; 以p≔next为编号令B⁡(k)≔⟨p,n,s⟩, θn≔Loading⁡(P′,UProv⁡(k,p)::acc,ω). 要求不满足时进入Unloading并带错误EConflict;
    • Spawn⁡(c,P′): 要求p⁡(c)不冲突; 插入子fiber⟨c,n,false,Inactive⁡(⊥)⟩, 名为m≔next, 并令θn≔Loading⁡(P′,USpawn⁡(m)::acc,ω). 冲突时进入Unloading并带错误EConflict.

所以L-Step在target⁡(n)=ω时总是适用的, Loading的fiber不会卡住.

第8.3节 卸载

  • L-Leaven: 若θn=Active⁡(acc,ω)且target⁡(n)≠ω, 则θn≔Unloading⁡(acc,ω,⊥).
  • L-Undon: 若θn=Unloading⁡(u::acc,ω,ζ)且下面按u分的前提成立, 则θn≔Unloading⁡(acc,ω,ζ), 并且:
    • UOp⁡(k,p,t,g): 若绑定p仍在, 把它的状态s改为g⁡(s);
    • UProv⁡(k,p): 守卫, 没有m≠n满足resolves⁡(m,p); 删除B⁡(k);
    • USpawn⁡(m): 要求m∉dom⁡(F), 即子fiber已被移除.
  • L-RetireChildn: 若θn=Unloading⁡(USpawn⁡(m)::_,_,_), m∈dom⁡(F)且¬τm, 则τm≔true.
  • L-Unloadedn: 若θn=Unloading⁡([],ω,ζ), 则θn≔Inactive⁡(ζ).
  • L-Removen: 若τn, θn=Inactive⁡(_), 且没有m满足πm=n, 则删除F⁡(n).

于是父fiber按LIFO撤到USpawn⁡(m)时, 先请求子fiber退出, 然后等它卸载并被移除, 再继续撤销更早的项; 在spawn之后登记的效应此时已经撤销完毕. 提供者撤到UProv⁡(k,p)时, 要等所有解析到p的依赖者先卸载. 这两处是演算中仅有的等待.

第8.4节 设计决定

与论文和Cordis相比, 主要的决定如下.

  • 移除: 只有一个外部请求O-Dispose, 条目在已请求移除, 已Inactive, 没有子fiber时由L-Remove自动删除. 比论文的Retire加Remove简单, 也不会因为过早删除而泄漏.
  • 卸载逐项进行: 论文一步应用整个累加器; 我们逐项撤销, 守卫才能精确到每个provision, USpawn才能等待子fiber.
  • LIFO串行: Cordis用Promise.all并发执行disposer. 后登记的效应往往依赖先登记的, LIFO不需要任何额外假设就是对的.
  • 放弃加载: 每个服务操作是原子步, 步与步之间都可以L-Divert. 不保留论文中让在途迭代落地的分支, 因为JS的await只出现在操作之间.
  • 失败之后: 增加O-Reset, 由外部决定是否重试, 比论文的永不重入实用.
  • 运行期效应: 不把累加器改成树, 而是用O-React把反应编码为子fiber. 子fiber本身就是一棵子效应树.
  • 隔离与可用性检查: 不加规则. 键是服务名加作用域标签, 隔离就是对组件表做键重命名, 见第9.6节; 在提供时求值的检查是程序自己就能做的判断.

第9章 元理论

这一章陈述演算的性质: 良构性被保持, 依赖顺序被遵守, 卸载精确地撤销效应, 系统不会死锁且会终止, 以及终态与执行顺序无关.

第9.1节 保持性

定理9.1.1. 不变式WF在初始状态成立, 并被每条规则保持. 它由以下几条组成:
  • 现存名字, 编号, USpawn中的子名字都小于next;
  • 子fiber的父fiber存在, 已安装, 且累加器中有对应的USpawn;
  • 现存fiber的p两两不相交;
  • 已解析的每个依赖都有绑定, 编号与视图一致, owner不是自己;
  • 已安装fiber的视图的键序列恰为d;
  • 每个绑定的owner存在, 已安装, k∈p⁡(owner), 且owner的累加器中有对应的UProv;
  • 累加器中的每个UProv⁡(k,p)都对应一个现存绑定, 编号为p, owner为自己;
  • 一个累加器中每个键至多有一个UProv.
证明. 对规则逐条检查. 有意思的情形如下. O-Insert, O-React和Spawn步都检查新组件的p与现存fiber不冲突, 所以不相交性保持. Provide步要求k∈p⁡(cn)且B⁡(k)未定义, 并同时在累加器里压入UProv, 所以绑定与累加器的对应保持. 撤销UProv时守卫保证没有其他已安装fiber解析到这个编号, 所以删除绑定不会破坏已解析的依赖都有绑定. L-Remove要求没有子fiber, 所以父fiber存在的条件保持. L-Begin取的视图就是target, 它的键序列恰为d, 并且只解析到Active的提供者.
◻

推论: 有子fiber或绑定的fiber一定已安装; 一个fiber卸载完毕时, 它的子fiber和绑定都已经不存在了. 论文的保持性只有4条不变式.

第9.3节 恢复精确性

选定fiber n, 沿执行维护一个影子存储: 其他fiber的操作与撤销, 所有绑定的创建与删除都照常进行, 只跳过n自己的操作与撤销. 不变式是: 对每个键, 把n在该绑定上尚未撤销的逆按LIFO依次作用于实际状态, 结果≃影子状态.

定义9.3.1. 称(a,b)在键k上可能相遇, 如果存在组件c和c′, 使得a作为对k的操作出现在body⁡(c)中, b出现在body⁡(c′)中, 并且当c=c′时c不提供任何键: meetk ⁡ ( a,b ) :⇔ ∃ c, c′ . a∈ opsk ⁡ ( body⁡ (c) ) ∧ b∈ opsk ⁡ ( body⁡ ( c′ ) ) ∧ ( c= c′ ⇒ p⁡ (c) =∅ ) . 假设(H)是: 可能相遇的操作对在不同令牌下撤销独立, meetk ⁡ ( a,b ) ∧ ta ≠ tb ⇒ RevertIndep⁡ ( a, ta ,b, tb ) . 定义中的蕴涵是说: 同一组件的两个操作, 只在该组件不提供任何键时才算可能相遇. 提供键的组件同时至多有一个实例 (各fiber的p两两不相交), 它的两个操作来自同一个fiber, 按LIFO撤销, 不需要假设.
定理9.3.2. 设所有服务操作良好, 且(H)成立. 设γ0满足不变式且n在其中没有待撤销操作, γ0⟶⁎γ是一次执行, σ^是沿这次执行得到的影子存储, 并且n在γ中也没有待撤销操作 (比如卸载完毕). 那么对每个键k, store⁡(γ)⁡(k)与σ^⁡(k)同时无定义, 或者 store⁡ (γ) ⁡ (k) ≃ σ^ ⁡ (k) , 其中store⁡(γ)⁡(k)=s当B⁡(k)=⟨_,_,s⟩. 换言之, 卸载n的结果, 就是同一次执行中略去n全部操作所得的结果, 不论其他fiber同时做了什么.
证明. 沿执行维护本节开头的不变式. 逐类检查步骤: n自己的操作把状态从s改为s′, 并压入逆g; 因为g⁡(s′)≃s, 先施新压入的逆就回到原来的情形, 而影子不动. n撤销一项时, 实际状态施加了这个逆, 待撤销的列表少了这一项, 两边的作用抵消. 其他fiber在同一绑定上执行操作b时, 影子也执行b; 需要把n的待撤销逆移到b之后, 这正是撤销独立的第一条, 而(H)保证n的操作与b可能相遇时满足它 (令牌不同, 因为令牌各自新鲜). 其他fiber的撤销项h需要与n的逆交换, 这是撤销独立的第二条. 绑定的创建与删除在两边同时发生; n仍有待撤销操作的绑定不会被删除, 这由守卫保证. 最后n没有待撤销操作时, 不变式说的就是实际存储≃影子存储.
◻
定理9.3.3. 运行期效应的撤销也是精确的: 从效应出现之前到它的子fiber被移除之后, 每个绑定的状态都≃略去该效应全部操作所得的状态.

与论文的定理61相比, 这里只要求可能相遇的操作对撤销独立, 不要求前进函数交换, 同一fiber内部不需要任何假设 (LIFO); 并且覆盖运行期效应.

第9.4节 进展与终止

定义9.4.1. 称c′在c之上, 记作c≺c′, 如果 p⁡ (c) ∩ d⁡ ( c′ ) ≠∅ , 或者c可能spawn c′, 即c′出现在c的程序的某个spawn中, 或是c的事件处理器. 一个状态是稳定的, 如果每个fiber n满足下列之一: { θn = Inactive⁡ (ξ) ∧ ¬ τn , 失败并停下 θn = Inactive⁡ (⊥) ∧ ¬ τn ∧ target⁡ (n) =⊥ , 不该运行 θn = Active⁡ ( _,ω ) ∧ target⁡ (n) =ω , 该运行且视图正确 特别地, 稳定状态中没有Loading或Unloading的fiber.
定理9.4.2. 设≺没有无限上升链c0≺c1≺⋯. 对满足不变式的γ, quiet⁡ (γ) ⇒ settled⁡ (γ) , settled⁡ (γ) ∨ ∃ n, ℓ∈ L⁡ (n) , γ′ . γ ⟶ℓ γ′ . 即没有生命周期规则可用的状态一定是稳定的, 不稳定的状态总有生命周期规则可走.
证明. 设没有生命周期规则可用, 但状态不稳定. 检查每种生命周期状态可以发现, 不稳定的fiber只可能处于Unloading, 并且卡在两处之一: 撤销UProv⁡(k,p)时还有已安装的m解析到p; 或撤销USpawn⁡(m)时子fiber m还在. 前一种情形, n提供了m声明的键, 后一种情形, n可能spawn m, 两种情形下m的组件都在n的组件之上. 并且m也不稳定: 前一种情形n已经不是Active, p不再可见, 所以target⁡(m)与m的视图不同; 后一种情形m已被请求移除 (否则L-RetireChild可用), 稳定的fiber不会带着这个标记. 于是m也卡在Unloading, 如此得到一条无限上升链, 与假设矛盾. 形式上, 这是沿≺的良基归纳.
◻
定理9.4.3. 设有r:C→ℕ和常数M,N, 使得 c≺ c′ ⇒ r⁡ (c) < r⁡ ( c′ ) <M , 并且每个程序的任一路径长度都不超过N. 那么从满足不变式的状态出发, 不存在无限的执行 γ0 ⟶ ℓ0 γ1 ⟶ ℓ1 ⋯ , 其中每个ℓi都是生命周期标签.
证明. 给每个fiber一个度量 (在target不变时它还能走的步数的上界), 状态的度量是按秩分层求和得到的向量, 低秩的分量在字典序中优先, 每一步生命周期规则都使它按字典序严格下降. 关键事实是: 一个fiber的步骤可能使秩更低的fiber的某条规则变得可用 (依赖者卸载后提供者才能撤销provision, 子fiber移除后父fiber才能撤销spawn), 但不会增加它们的度量; 它可能增加的只有秩更高的fiber的度量, 比如新spawn的子fiber.

与论文的定理66相比, 没有定量的界.

第9.5节 合流

合流分五层证明, 每层在前一层之上.

定理9.5.1. [控制层, 无spawn]: 设组件都不spawn, 有定理9.4.3中的秩r和界M,N, 并且每个组件的程序的每条到达Done的路径都提供了它可能提供的所有键 (论文的定义69). 设γ0满足不变式, γ0⟶⁎γ1和γ0⟶⁎γ2只走生命周期规则, γ1和γ2都quiet且没有失败的fiber. 用Fi, Bi表示γi的注册表和绑定, cn,i, θn,i表示Fi⁡(n)的组件和生命周期状态, 则 dom⁡ ( F1 ) = dom⁡ ( F2 ) c n,1 = c n,2 θ n,1 = Active⁡ ( _,_ ) ⇔ θ n,2 = Active⁡ ( _,_ ) owner⁡ ( B1 ⁡ (k) ) = owner⁡ ( B2 ⁡ (k) ) 第二, 三式对所有n∈dom⁡(F1)成立, 第四式对所有k成立.
证明. 论证不比较两次执行的过程, 而是刻画终态. 在没有失败fiber的quiet状态中, 一个fiber是Active当且仅当它没有被请求移除, 且它声明的每个键都由一个Active的fiber提供. 这里用到了关于Done路径的前提: Active的fiber提供了它可能提供的所有键. 这样, Active的fiber之集合是一个不动点方程的解, 方程只依赖起点. 沿秩归纳可知这个方程只有一个解. 秩的前提不能去掉: 若c提供k1而依赖k2, c′提供k2而依赖k1, 则两者都Active和两者都不Active都是这个方程的解.
◻
定理9.5.2. [服务状态, 无spawn]: 在上一个定理的设定下, 再设服务满足合流假设 (见定理9.5.5). 则对每个键k, 若B1⁡(k)=⟨_,_,s1⟩且B2⁡(k)=⟨_,_,s2⟩, 则s1≃s2.
证明. 分三步. 第一, 在一次执行中, 每个绑定的状态≃它的初始状态再依令牌顺序执行它上面尚未撤销的操作. 第二, 每个已加载的fiber的累加器对应一条理想轨迹: 单独运行它的程序, 每个操作的回答都在它解析到的provision的初始状态上依次执行这个fiber自己在该键上先前的操作得到, 不计其他fiber的操作. 可能相遇的操作可交换, 所以其他fiber穿插进来的操作不改变这里看到的结果, 所以理想轨迹只由程序和初始状态决定; 沿秩归纳, 两个终态中对应的Active fiber有相同的轨迹. 第三, 于是每个键上待撤销的操作在两个终态中是同一组, 只是顺序可能不同; 由可交换性, 重排不改变终态的≃类.
◻
定理9.5.3. [带spawn]: 设定同上, 但允许组件spawn, 并且启动时spawn的子fiber不被直接dispose. 则两个终态在重命名的意义下一致: 存在规范名, 使得fiber, 组件, 是否Active, 绑定都一一对应. 不论两个终态如何到达, 只要根fiber对应, 它们就一致.
证明. 名字依赖于调度, 所以先给每个fiber一个规范名: 根fiber保留自己的名字, 子fiber由父fiber的规范名和它在父fiber的spawn中的位置命名. 父fiber是否spawn, spawn什么, 取决于它的操作的结果, 所以对应关系要沿秩归纳建立: 对应的fiber有相同的组件和理想轨迹, 因而spawn出对应的子fiber. 其余部分与无spawn的情形相同. 这里还需要一个不变式: Loading和Active的fiber的子fiber都还活着; 直接dispose启动时spawn的子fiber会破坏它, 见下文.
◻
定理9.5.4. [编排与生命周期交错]: 从初始状态出发, 接受相同编排输入 (以插入次序而不是名字指称根fiber), 并以任意方式穿插生命周期步的两次执行, 若都到达quiet且没有失败fiber, 则在重命名意义下一致. 特别地, 终态与静态组装(先全部插入再运行)的结果一致.
证明. 插入得到的名字依赖于调度, 所以输入以插入次序指称根fiber. 沿执行记录一本账: 对每个插入次序, 若它没有被dispose, 终态中恰有一个根fiber, 组件就是插入的那个. 早先的插入, dispose, 重启, 重置除了留下的根fiber之外不留痕迹. 于是两个终态的根fiber按插入次序一一对应, 再用上一个定理中不论终态如何到达, 只要根fiber对应就一致的那一半即可.
◻
定理9.5.5. [服务的组合]: 称服务满足合流假设, 如果
  1. 每个操作都良好;
  2. 操作给出的逆与所在的状态无关: 若runats1=(_,g1,_), runats2=(_,g2,_), 则∀x.g1⁡(x)≃g2⁡(x);
  3. 令牌不影响后继(在≃意义下)和结果;
  4. 可能相遇的操作在不同令牌下可交换, 并且满足撤销独立的第一条 (只需在a之后可能出现的状态上).
则上面三个定理对任何满足合流假设的服务成立; 两个满足合流假设的服务之和也满足它.

合流不覆盖O-React, 也只允许dispose根fiber. 原因是: 启动时spawn的子fiber若被直接dispose, 父fiber在一次执行里保留原生命期, 在另一次执行里重新加载并重新spawn, 两次的终态确实不同; 这在Cordis中同样成立, 不是模型的人为限制. 保持性, 顺序, 恢复精确性, 进展, 终止都覆盖O-React.

论文的定理73(1)构造了按依赖顺序排列episode的规范执行; 我们只断言终态与静态组装一致, 并把静态组装能否无失败地到达quiet作为前提. 引理68, 70(支持集)只在无spawn的控制层有对应, 有spawn时由规范名对应.

第9.6节 派生形式

定理9.6.1. 隔离是对组件表的键重命名: 键取为服务名加作用域标签, 被隔离的子树换一个标签. 重命名保持各定理对组件的假设: 程序有界, 每条到达Done的路径提供组件可能提供的所有键, 秩的单调性, 以及独立性 (此时要对同一服务名上任意两个组件的操作成立, 因为同一组件可以在多个作用域中同时运行).

所以对任意组件表陈述的定理都直接适用于隔离, 不需要论文定义28的领域表. 论文的拦截 (定义30, 31) 视为传给服务的数据, 不影响生命周期, 本文不讨论.
