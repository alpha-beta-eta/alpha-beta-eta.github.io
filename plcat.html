编程语言范畴论

前言

这些是一门面向程序设计语言研究者的范畴论课程的讲义. 我想说, 这份讲义和这门课程都是被逼出来的: 范畴论的用处无法回避, 我才不得不去学习和理解一些范畴论. 我不会把自己称作范畴论学者, 这门课也与我以往尝试讲授的任何课程都很不一样. 我在这门课上的目标, 是梳理出我认为范畴论中必然出现的东西, 并以我觉得最合理的方式呈现出来. 当然, 没有John, 这一切都不可能实现, 真正理解这里所有内容的人是他.

许多程序设计语言研究者和学生都曾在某个时候接触过范畴论. 大多数人第一次见到它, 可能是在学习Haskell时看到monad (单子)和functor (函子)这样的词. 也有些更偏数学的人, 是在学习lambda演算时接触到它的, 他们听说了Scott, Smyth和Plotkin关于无类型lambda演算模型论的著名成果 [34]. 你来到这里, 很可能是因为你在某处见过范畴论, 想知道为什么需要它, 或者怀疑它是否真的有必要.

就我而言, 范畴论第一次出现在我自己的研究中, 并迫使我停下来去理解它, 是因为Heunen等人关于拟Borel空间的论文. 那是我读研究生的第二年, 我得承认这篇论文让我非常发怵. 它可怕地结合了两点: (1) 似乎对我眼下的研究非常重要, (2) 完全无法理解. 简而言之, 这篇论文为一种支持连续概率分布的高阶概率编程语言提出了一种指称语义, 称为拟Borel空间 (quasi-Borel spaces, QBS). 我当时是, 现在也仍然是概率程序设计语言的研究者, 所以这个结果似乎至关重要: 我喜欢函数! 然而当时我甚至看不出这件事为什么一开始就很难做! 如果你连一个问题的动机都理解不了, 那么想理解它的解法就只能祝你好运了.

论文第二段恰好给出了核心难题:

这些语言中的程序可能会把高阶函数与连续分布结合起来, 甚至在函数上定义概率分布. 但是, 概率论标准的测度论形式化不能很好地处理高阶函数, 因为可测空间范畴不是笛卡尔闭的. [14]

这句话我当时完全看不懂. 它唯一的引用是一篇1961年的论文, 题为Borel structures for function spaces (函数空间上的 Borel 结构) [3]. 这篇论文和我当时想读懂的那篇一样难以理解, 甚至更难! 我已经力不能及, 只好先放下, 而且很多年都没能读懂这篇论文.

当时, QBS论文像晴天霹雳一样突然出现, 严重动摇了我对自己做研究能力的信心. 但在过去8年里, 我逐渐意识到, 这篇看起来像是神来之笔, 又像来自外星的论文, 在某种意义上几乎是若干简单想法必然会走到一起的结果. 原来, 拟Borel空间的想法并不诞生于概率论, 而是来自一个看似毫不相干的数学角落: 微分几何与拓扑. 去年我和Max New聊起QBS, 他告诉我, 他读研究生时就想到过这套构造, 但因为它与微分空间 (diffeological spaces) 的关系看起来太直接, 他没有动力把它完整地发展出来. 这些结果在结构上非常相似, 以至于在训练有素的专家眼里, 那篇庞大的QBS论文几乎显得过于平凡! 这是我们对为什么要学范畴论?这个问题的第一个回答: 它把不同数学领域之间存在的类比精确化, 让你可以用非常相似的工具解决不同的问题.

如果这是我唯一一次遇到范畴论, 我不会在它上面投入足够多的精力, 以至于尝试开一门相关的课. 但范畴论一再出现. 我后来与范畴论的接触, 主要是由我的博士生John推动的, 他正在帮我讲授这门课并撰写这份讲义. 这个故事要从Lilac [22] 说起. Lilac是一种概率分离逻辑, 是我们在John读博的头两年里开发的. 在讲Lilac之前, 我们需要先简要讨论一下分离逻辑. 我保证我们会讲到范畴论的.

分离逻辑是描述资源的逻辑. 它们在程序设计语言领域被广泛使用, 用来建模内存等资源如何在程序中流动. 具体来说, 考虑下面这个C程序:

void foo(int* x, int* y) {
  for(int i = 0; i < 3; i++) {
    *x += *y;
  }
}
有人看到foo可能会觉得它写得非常低效: 它完全可以优化成直接把3*y加到x上. 但如果x和y指向内存中的同一个位置 (也就是说, 它们互为别名) 呢? 那么这个优化就不再成立, 因为y在循环的每一次迭代中也会被修改. 由于C编译器必须做最坏的假设, 它不能进行这个优化.

分离逻辑为我们提供了一种描述内存所有权的语言, 让我们可以告诉编译器这些指针不会互为别名. 要让这个优化成立, foo必须有一个前置条件, 断言这两个参数不会互为别名. 在分离逻辑中, 这个前置条件可以写成: [ x↦− ] ⁎ [ y↦− ]

⁎称为分离合取 (separating conjunction): 它表示两个命题[x↦−] (读作x指向某个位置) 和[y↦−]分别在堆中互不相交的部分上成立, 因此x和y不可能互为别名.

然而, 内存并不是程序中唯一的一种资源: 随机性也是一种很自然的资源. 在概率程序中, 我们可能想表达这样的命题: [ x∼ Bern⁡ 1/2 ] ⁎ [ y∼ Bern⁡ 1/2 ] 它表示两个变量x和y是相互独立的Bernoulli随机变量. 除了概率之外, 程序显然还可能涉及许多其他类型的资源, 比如网络套接字, 互斥锁等. 难道我们必须为每一种资源都从头开发一套分离逻辑吗?

这引出了为什么要学范畴论?的第二个回答: 它能让一些看似随意的选择变成必然的结果. 我们会看到, 分离合取有一个范畴论的描述, 可以用一种叫做Day卷积 (Day convolution)的构造计算出来 [11, 6]. 如果你对⁎的解释来自这个构造, 那么它会自动满足分离合取应当满足的许多其他良构性要求. 这说明了范畴论如何为种类繁多的资源交互带来清晰的理解: 它指出你做出的哪些决定是真正新的, 哪些只是推论. 它会逼你出牌, 而当你不知道该出哪张牌时, 这一点非常有用.

到这里, 我已经确信, 对于任何从事程序设计语言研究的人来说, 掌握一些范畴论都是值得的投入, 尤其是研究概率这类特殊效应 (exotic effects) 或研究程序逻辑的人. 我也有些自负: 我认为范畴论并不难理解, 尤其是当你被我们将在课程中逐步介绍的一些应用充分激发了兴趣时. 这门课的目标读者是2017年的我. 那时的我在自己的领域里看到一篇重要论文, 却因为它熟练运用了范畴论的思想而觉得它遥不可及. 我希望我们能把其中一些思想讲得足够清楚, 让你看到这些优雅思想的必然性, 而不是被它们的晦涩难懂淹没.

第1章 为什么需要范畴?

人们最常遇到范畴论的地方之一是语义. 为了刻画为何范畴出现在这里, 以及它们的典型用途, 我们将会考虑一个每个程序员都遇到过的具体例子: 我们想要建立什么操作会改变我们程序的行为, 什么操作则是无关紧要的.

考虑一个微型语言Calc, 其由let绑定, 序对, 以及布尔构成: M,N ⩴ letxbeMinN |x|true|false | ifMthenNelseO | ⟨ M,N ⟩ | fst⁡M | snd⁡M A,B ⩴ A×B |Bool Calc有着一个简单类型系统: Γ⊢ true:Bool Γ⊢ false:Bool Γ⊢ M:Bool Γ⊢ N:A Γ⊢ O:A Γ⊢ ifMthenNelseO :A Γ⊢ M:A Γ⊢ N:B Γ⊢ ⟨ M,N ⟩ : A×B x:A ∈Γ Γ⊢ x:A Γ⊢ M: A×B Γ⊢ fst⁡M :A Γ⊢ M: A×B Γ⊢ snd⁡M :B Γ⊢ M:A Γ, x:A ⊢ N:B Γ⊢ letxbeMinN :B 以下是一个或许我们想要澄清的简单变换: 两个let绑定可以交换, 如果它们的定义没有提及对方. letxbeMin ( letybeNin ⟨ x,y ⟩ ) =? letybeNin ( letxbeMin ⟨ x,y ⟩ ) 从直觉上说, 这个等式成立是因为Calc程序没有副作用. 要证明这个直觉是对的, 我们可以证明这两个程序具有相同的含义. 为此, 我们需要给Calc程序一个语义.

第1.1节 Calc的一个指称语义

设计语义的第一步是选择用于陈述语义的元语言. 元语言应该是能够无歧义描述和使用的形式语言, 因为其本身的意义应当在我们解释程序时理所当然. 对于像Calc这一的简单语言, 一种自然的选择是集合与函数的语言.

用这种元语言, 我们可以给Calc程序一个指称语义, 也就是用所选的元语言来描述语法层面的程序的含义. 类型将被解释为集合: (1.1) ⟦Bool⟧ = { 0,1 } (1.1) (1.2) ⟦ A×B ⟧ = ⟦A⟧ × ⟦B⟧ (1.2) 布尔类型指称二元素集合{0,1}, 积类型A×B指称A的指称与B的指称的笛卡尔积. 利用对类型的这种解释, 我们可以给出对类型上下文 (typing contexts) 的一种解释: ⟦•⟧ = {⋆} ⟦ Γ, x:A ⟧ = ⟦Γ⟧ × ⟦A⟧ 空上下文•被解释为单元素集{⋆}, 而上下文扩展则解释为笛卡尔积. 将这些拼在一起, 该解释将⟦Γ⟧定义为具有形状Γ的替换集合, 其元素是将Γ中的变量x映射为⟦Γ⁡(x)⟧的元素的函数.

使用这种对于类型和上下文的解释, 我们可以将Calc项Γ⊢M:A解释为函数⟦Γ⊢M:A⟧:⟦Γ⟧→⟦A⟧: ⟦true⟧ = γ↦1 ⟦false⟧ = γ↦0 ⟦ ifMthenNelseO ⟧ = γ↦ { ⟦N⟧ ⁡γ , ⟦M⟧ ⁡γ =1 ⟦O⟧ ⁡γ , ⟦M⟧ ⁡γ =0 ⟦ ⟨ M,N ⟩ ⟧ = γ↦ ( ⟦M⟧ ⁡γ , ⟦N⟧ ⁡γ ) ⟦ fst⁡M ⟧ = γ↦ π1 ⁡ ( ⟦M⟧ ⁡γ ) ⟦ snd⁡M ⟧ = γ↦ π2 ⁡ ( ⟦M⟧ ⁡γ ) ⟦x⟧ = γ↦ πx ⁡ (γ) ⟦ letxbeMinN ⟧ = γ↦ ⟦N⟧ ⁡ ( γ [ x↦ ⟦M⟧ ⁡γ ] ) 我们可以使用这种语义来validate先前的重排, 因为等式两边指称着相同的函数. ⟦ letxbeMin ( letybeNin ⟨ x,y ⟩ ) ⟧ = γ↦ ( ⟦M⟧ ⁡γ , ⟦N⟧ ⁡γ ) = ⟦ letybeNin ( letxbeMin ⟨ x,y ⟩ ) ⟧ 但请注意, 这里有一些微妙之处! 我们在这里依赖元语言中函数相等的概念来判定相等. 两个函数f,g:A→B被认为相等, 当且仅当它们外延相等 (extensionally equal), 也就是说, 对所有a∈A, 都有f⁡(a)=g⁡(a). 如果仔细展开这两个语义, 我们会看到函数⟦M⟧和⟦N⟧是以不同的顺序复合的. 在集合语义下, 这个复合顺序无关紧要, 因为它不会改变输入输出行为.

第1.2节 一般性的需要

总结一下刚才的过程: 为了证明一个涉及let绑定重排的自然程序等价, 我们用集合与函数给出了Calc的指称语义. 然后, 元语言的一个性质, 即函数的外延相等, 直接推出了这一改写是保持语义的.

这种指称推理方式在验证程序等价时效果相当好, 由此引出一个问题: 它能多好地推广到其他类型的程序设计语言和分析上? 我们可能希望沿着几个有趣的方向推广这类论证:

  1. 推广到具有更有趣的效应的语言, 比如随机性, 非确定性或可变状态;
  2. 推广到具有更有趣的特性的语言, 比如高阶函数或更有趣的类型系统.
我们会看到, 用集合与函数作为元语言其实相当不方便. 这将成为我们发展范畴论的核心动机: 范畴论是另一种更灵活的元语言, 可以用来给程序 (以及程序逻辑等其他对象) 赋予语义. 不过在看到这一点之前, 我们先分别看一个这两类推广的例子.

第1.3节 泛化1: 概率效应

我们来看一个推广到具有有趣的概率效应的语言的例子. 考虑下面这个叫做TinyPPL的小型概率编程语言. 它在Calc的基础上增加了一个原语flip, 用来生成随机布尔值: TinyPPL M,N ⩴ ⋯|flip TinyPPL

显然, 这种重排是一个普遍的现象, 我们希望在许多具有不同语义解释的语言中研究它. 范畴论为语义domain的这种性质起了一个名字: 交换性 (commutativity). 此外, 范畴论还提供了一套语言, 用来描述各种各样效应的性质. 概率是单子 (monad) 的一个例子, 而这个单子是交换的. 因此, 这类改写对所有交换单子都成立.

第1.5节 结语

第2章 范畴

作为元语言, 集合与函数作为纯函数式编程的模型最能发挥效用, 其程序被想成是一个黑盒, 对于每个输入有唯一确定的输出. 但是现实程序很少是纯函数式的: 野生的程序基本上都需要操纵资源 (指针, 文件, 锁), 与其环境进行交互 (输入和输出), 并使用复杂的控制流构造 (异常, 协程).

范畴论提供了一种更换周遭 (ambient) 元语言的框架: 它给出一些系统化的技术, 用更适合建模实际编程特性的构造来取代集合与函数. 每个范畴都代表一种元语言的选择. 集合与函数属于集合范畴Set, 我们稍后会遇到它. 把Set换成其他范畴, 就能得到更适合建模编程语言特性的元语言:

  • 传统的domain论活在domain的范畴. 它研究无类型lambda演算, 以及Haskell这类递归函数式编程. 作为元语言, 它支持任意递归定义和递归类型.
  • 许多现代语义学工作在步进索引集合 (step-indexed sets) 的范畴中进行. 作为元语言, 它支持非常强的递归类型. 我们会在讨论预层 (presheaves) 时遇到这个范畴.
  • 操作资源的程序属于资源化集合 (resourceful sets) 的范畴, 这些范畴用于定义现代分离逻辑. 我们会在讨论Day卷积时遇到它们.
  • 普通的连续概率属于可测空间的范畴, 它的高阶推广属于拟Borel空间 (quasi-Borel spaces). 如果时间允许, 我们也许会讲到这些范畴.
