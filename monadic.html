模块化单子语义和编译

第1章 引论

第1.1节 概览

指称语义 [Stoy, 1977] 是编程语言理论中最重要的发展之一. 它为编程语言提供了精确的数学描述, 可用于语言的设计与实现以及程序的推理. 例如, 指称语义的进展促进了语言特性的澄清, 推动了更一致的编程语言设计, 并催生了新的编程构造.

然而, 人们很早就认识到, 传统的指称语义缺乏模块性和可扩展性 [Mosses, 1984] [Lee, 1989]. 这被视为将指称语义应用于实际编程语言的一大障碍.

在本论文中, 我们利用编程语言理论中的一项新发展——单子方法 [Moggi, 1990]——来构建结构化的指称语义. 由此产生的模块化单子语义实现了高度的模块性和可扩展性. 它能够将各个编程语言特性封装为可重用的构建模块, 并通过组合所需的特性来定义编程语言.

由于模块化单子语义本质上就是一种结构化的指称语义, 所有的等式推理方法均可适用. 此外, 我们将展示模块化单子语义如何进一步促进推理, 它允许我们为编程语言特性指定公理, 并构造可重用的模块化证明.

模块化单子语义可以使用现代编程语言来实现, 例如Haskell [Hudak et al., 1992], ML [Milner et al., 1990] 或Scheme [Clinger and Rees, 1991]. 其结果是一个模块化的解释器. 我们发现, Gofer (以及Haskell 1.3) 中相对较新的构造子类概念特别适合于表示模块化解释器中一些相当复杂的类型关系.

我们的工作可直接应用于语义导向的编译器构造. 我们将提出一种基于单子语义和单子程序变换的编译方法, 并通过重新定向一个Haskell编译器来验证我们的想法.

在介绍模块化单子语义之前, 我们将在下一节给出一个示例, 以说明传统指称语义缺乏模块性. 本文的表述遵循传统的指称语义风格, 并辅以类似于Haskell或ML的类型声明句法. 我们假设读者具备指称语义和函数式编程的基本知识.

第1.2节 指称语义的模块性缺乏

让我们首先来看一个简单算术语言的语义: E : Term→Value E⁡ ⟦n⟧ = n E⁡ ⟦ e1 + e2 ⟧ = E⁡ ⟦ e1 ⟧ + E⁡ ⟦ e2 ⟧

指称语义将源语言中的项映射为元语言中的值. 源语言的项用⟦⟧括起来. 右侧的n和+符号对应于元语言中的数字和加法算术运算的概念.

译者注记. 其实就指称语义而言, ⟦⟧记号一般就相当于指称函数本身了. 不过指称函数可能不止一个, 所以有时可能需要某种手段进行标记. 有的人选择下标, 有的人选择在前面加上符号. 当然, 像本文一样理解也没有任何问题.

模块性的一个重要度量方式是语义描述能否被扩展以纳入新的编程语言特性. 例如, 如果我们用变量和函数来扩展源语言, 就需要引入一个环境——即从变量名到值的映射: E : Term→Env→Value E⁡ ⟦n⟧ = λρ.n E⁡ ⟦ e1 + e2 ⟧ = λρ. E⁡ ⟦ e1 ⟧ ⁡ρ + E⁡ ⟦ e2 ⟧ ⁡ρ E⁡ ⟦v⟧ = λρ. ρ⁡ ⟦v⟧

尽管数字与环境无关, 我们仍然必须修改数字的语义, 以适应新引入的环境参数. {译注: 此处说的数字是源语言中的, 一个更好的名字或许是numeral.} 同样, 环境参数必须递归地传递给e1+e2的子表达式, 即便算术运算本身与环境无关.

如果我们进一步在语义中加入延续 (例如, 为了支持顺序运算符;), 就必须再次修改数字的语义: E : Term→Env→ ( Value→Ans ) →Ans E⁡ ⟦n⟧ = λρ. λk. k⁡n E⁡ ⟦ e1 + e2 ⟧ = λρ. λk. E⁡ ⟦ e1 ⟧ ⁡ρ ⁡ ( λi. E⁡ ⟦ e2 ⟧ ⁡ρ ⁡ ( λj. k⁡ ( i+j ) ) ) E⁡ ⟦ e1 ; e2 ⟧ = λρ. λk. E⁡ ⟦ e1 ⟧ ⁡ρ ⁡ ( λx. E⁡ ⟦ e2 ⟧ ⁡ρ ⁡k )

译者注记. 为了完整性, 我们加上原文可能是忘了的变量的语义. E⁡ ⟦v⟧ = λρ. λk. k⁡ ( ρ⁡ ⟦v⟧ )

总而言之, 为了向源语言添加新特性, 我们必须对传统指称语义进行全局修改. 传统指称语义缺乏模块性这一问题早已被人们所认识 [Mosses, 1984] [Lee, 1989]. 它被视为将指称语义应用于现实编程语言的最大障碍.

在下一节中, 我们将展示如何通过使用一种称为单子的抽象机制来增强模块性.

第1.3节 单子——一种抽象机制

我们将使用一个类型构造子M和两个函数: return : a→ Ma bind : Ma → ( a→ Mb ) → Mb

这些构造的直觉性含义如下:

  • Ma: 返回类型为a的值的计算.
  • bindc1(λv.c2): 首先计算c1, 将结果绑定至v, 然后计算c2的计算.
  • returnv: 平凡的计算, 其直接返回v作为结果.

接下来, 我们使用M, bind和return为算术表达式写下一个参数化语义: E : Term→ MValue E⁡ ⟦n⟧ = returnn E⁡ ⟦ e1 + e2 ⟧ = bind ( E⁡ ⟦ e1 ⟧ ) ( λi. bind ( E⁡ ⟦ e2 ⟧ ) ( λj. return ( i+j ) ) ) 语义函数E将项映射为计算 (其具有类型MValue). E⁡⟦n⟧的语义是返回n作为结果的平凡计算. E⁡⟦e1+e2⟧的语义是先计算E⁡⟦e1⟧, 将其结果绑定至i, 然后计算E⁡⟦e2⟧, 将其结果绑定至j, 最终返回i+j的计算.

译者注记. 对于原文这里的E⁡⟦n⟧和E⁡⟦e1+e2⟧的语义 (semantics), 个人认为使用意义 (meaning)更为贴切.

参数化语义的优势在于, 根据我们如何实例化M, bind和return, 可以得到我们所选择的不同语义. 图1.1展示了如何将算术语义实例化为上一节中描述的平凡语义和基于环境的语义. 在本论文的后续部分, 我们将看到, 对M, bind和return进行适当的定义, 还可以导出其他语义 (例如, 基于延续的语义).

类型构造子M连同两个函数return和bind, 被称为一个单子 (monad). 上面为算术表达式定义的参数化语义被称为单子语义 (monadic semantics). 单子语义可以使用不同的潜在单子 (underlying monad)来实例化. 要向单子语义中添加一个新特性, 我们只需添加该新特性的语义描述, 并更改潜在单子, 而无需修改现有特性的语义描述.

第1.4节 论文的背景和组织方式

本论文在前人工作的基础上, 探讨单子和单子语义的理论与实际应用. 单子的概念源于范畴论 [Mac Lane, 1971]. 使用三元组 (bind, return和类型构造子) 来表述单子的方式归功于Kleisli. Moggi [Moggi, 1990] 最先提出单子是构造指称语义的有用工具. Wadler的早期工作 [Wadler, 1990] 展示了单子与函数式编程之间的关系. 近来, 人们对使用单子来构造模块化语义和模块化解释器产生了极大的兴趣 [Wadler, 1992] [Jones and Duponcheel, 1993] [Espinosa, 1993] [Steele Jr., 1994].

在第2章中, 我们将为广泛的编程语言特性呈现模块化单子语义. 我们将展示单子转换器 (monad transformer) 如何捕获各个特性, 以及提升 (lifting) 如何捕获不同特性之间的交互.

在第3章中, 我们将研究单子和单子转换器的理论. 这包括例如单子转换器和提升的形式化性质. 我们将使用单子律和公理, 在比传统指称语义更高的层次上进行等式推理.

在第4章中, 我们将展示单子和单子转换器的形式化概念如何自然地融入Gofer [Jones, 1991] 的类型系统. 通过在Gofer中实现模块化单子语义, 我们可以获得一个模块化解释器.

在第5章中, 我们将把单子语义应用于语义导向的编译. 我们将展示如何利用单子框架的模块性和推理能力, 推导出一个有效且可证明正确的编译方案. 我们将通过构建一个可重定向的Haskell编译器来检验我们的一些想法.

在整篇论文中, 我们将使用一种共同的源语言来讨论单子语义, 模块化解释器和编译中的各种问题. 这个源语言将于下一节引入.

第1.5节 源语言

本论文中所考虑的源语言具有多种特性, 包括不同的函数调用机制, 命令式特性, 第一级延续, 追踪 (用于调试), 以及非确定性.

第1.6节 记号

为清晰起见, 我们采用以下缩略形式: E : Term→ MValue E⁡ ⟦ e1 + e2 ⟧ = bind ( E⁡ ⟦ e1 ⟧ ) ( λi. bind ( E⁡ ⟦ e2 ⟧ ) ( λj. return ( i+j ) ) ) ⇓ E : Term→ MValue E⁡ ⟦ e1 + e2 ⟧ = { i← E⁡ ⟦ e1 ⟧ ; j← E⁡ ⟦ e2 ⟧ ; return ( i+j ) }

这种记号类似于Haskell中的do语法 [Peterson and Hammond, 1996], 也与单子概括式 (monad comprehension) [Wadler, 1990] 有一定的相似之处. 需要注意的是, 尽管具有命令式的外观, 单子语义仍然是由lambda表达式和函数应用所构成的. 我们将以可互换的方式使用bind和这种缩略形式, 完全取决于哪一种更为方便.
