deepseek harness笔记2

本文重新组织论文A Programming Paradigm for Spatiotemporal Composability的第3章和第4章, 并以插件运行时Cordis及其在dsh中的使用为背景. 这不是翻译: 定义和定理的形状按本文的需要重新安排, 论文的说法只在对照时提到. 目标是验证插件的生命周期性质, 插件的业务逻辑不在范围之内.

重构遵循以下几条原则.

  1. 论文和Cordis都不是权威. 每个设计点都选合理, 直接, 简单的方案; Cordis的做法若体现了局部的最佳实践就跟着它.
  2. 所有跨组件共享的可变状态都是某个服务的状态, 不设另外的环境部分.
  3. 程序是归纳类型, 看不到状态, 只能通过操作的结果决定下一步. 所以组件只碰自己声明过的东西, 这是由构造保证的.
  4. 服务状态从一开始就配备等价关系≃, 控制部分 (生命周期, 名字, 绑定的身份) 用严格相等.
  5. 定理的最终形状是: 若每个服务满足它的规格, 每个插件满足它的义务, 则整个系统满足生命周期性质 (定理6.7.4).

出发点是: 插件卸载时, 它对共享状态做过的每件事都必须撤掉, 所以每个改动共享状态的操作都要给出它的逆; 逆可以依赖于操作作用前的状态, 比如把x设为5的逆是把x改回原来的值. 另一方面, 插件通过服务相互依赖, 提供者撤走时依赖者必须先停下.

第1章到第5章给出模型: 服务, 程序, 组件与fiber, 以及生命周期规则. 第6章证明元理论, 每个定理需要的服务假设在它所在的节里引入. 附录A给出单个组件的语义 (论文3.1节的对应物), 附录B说明服务的等价关系应该怎样取, 附录C逐条对照论文, 附录D列出各定理在Rocq形式化中的对应. 正文的定理不依赖附录; 论文中本文的论证用不到的部分不再复述, 只在对照表中列出.

主要结果如下, 其中的术语 (fiber, Active, 撤销独立, 秩等) 在正文中定义.

  • 保持性与顺序: 不变式被每条规则保持; fiber只针对Active的提供者开始加载, 提供者比依赖者活得久 (定理6.1.1, 定理6.2.1).
  • 恢复精确性: 若服务的操作良好, 且可能相遇的操作撤销独立, 则卸载一个fiber的结果, 等于同一次执行中略去它的全部操作所得的结果 (定理6.3.5).
  • 进展与终止: 若依赖与spawn关系良基, 没有规则可用的状态都是稳定的; 再有秩和程序长度的界, 就没有无限的执行 (定理6.4.2, 定理6.4.3).
  • 合流: 再设可能相遇的操作可交换, 且每条到达Done的路径提供组件可能提供的全部键, 则不同调度到达的静止终态在重命名意义下一致, 并与静态组装的结果一致 (定理6.5.6).
  • 汇总: 以上性质按服务规格的两部分和组件义务的各条重新组织为一个定理: 服务一侧只依赖一个操作上的关系, 插件一侧只需逐条检查义务 (定理6.7.4).

第1章 服务

所有跨组件共享的可变状态都放在服务里. 服务是一个记录, 包含状态类型, 等价关系和操作.

定义1.1. 一个服务Σ由以下资料组成: 状态类型S, 其上的等价关系≃, 操作类型Op (参数已经放进操作里), 结果类型Out, 以及 run: Op→Tok→S→ Maybe ( S× End⁡ (S) ×Out ) . 其中End⁡(S)≔S→S, MaybeA是A加上表示失败的None, Tok=ℕ是运行时交给这次操作的新鲜令牌, 用于事件钩子这类生成出来的身份 (JS中由对象身份充当).

全系统只有一个服务Σ, 不是每个键一个; 需要多种服务时先取它们的和, 这样避开了依赖类型的映射. 操作作用在状态上, 给出新状态, 这一步的逆, 以及结果. 结果是程序获得信息的唯一途径, 也是观察者区分状态的依据, 见附录B.

定义1.2. 操作a在令牌t下良好, 当且仅当
  1. 带见证: 若runats=(s′,g,o), 则g⁡(s′)≃s;
  2. 尊重≃: 若s1≃s2, 则runats1与runats2都是None, 或分别是(s1′,g1,o)和(s2′,g2,o), 其中s1′≃s2′且∀x.g1⁡(x)≃g2⁡(x);
  3. 给出的逆尊重≃: 若runats=(s′,g,o), 则∀x,y.x≃y⇒g⁡(x)≃g⁡(y).
例子1.3. 按名字索引的注册表 (如ctx.tools): 状态是名字到可选值的映射, 逐点比较. Register⁡(x,v)在x已被占用时失败, 逆是删去x; Lookup⁡(x)读出x处的值, 逆是恒等. 每个操作都良好. 名字不同的操作互不干扰; 同名的两次登记中后一次失败, 所以它们谁先谁后是看得出来的.
例子1.4. 有序事件总线 (如ctx.on): 状态是钩子的列表, 每个钩子是令牌和回调的对. 以令牌t注册回调c就是在表尾加入(t,c), 逆是删去令牌为t的钩子; 分发按顺序返回回调的列表, 逆是恒等. 两次注册不可交换, 因为分发看得到顺序 (附录B说明不论取哪个等价关系都是如此). 令牌用在逆上: Cordis的旧做法按回调注销, 即删去第一个回调为c的钩子; 若c已经注册过一次, 撤销第二次注册删掉的是第一次的钩子, 所以它不是精确的逆. 去掉分发并忽略顺序, 就得到监听器注册: 状态是回调的列表, 按多重集比较, 注册的逆是删去第一个c. 在多重集的意义下删去哪一个c都一样, 所以这里不需要令牌.

第2章 程序

组件的行为是: 每一段执行一个操作, 再根据结果选择后续. 我们把它直接做成一个归纳类型. 程序在存储上的语义见附录A, 正文只用到它的语法.

定义2.1. 设K是键的集合. 对键集d,p⊆K, 程序P∈Progd,p由以下文法生成: P⩴ Done|Fail| Call⁡ ( k,a,κ ) | Provide⁡ ( k,s,P ) | Spawn⁡ ( c,P ) , 其中Call⁡(k,a,κ)要求k∈d∪p, Provide⁡(k,s,P)要求k∈p, 延续κ:Out→Progd,p和子程序都在Progd,p中. Call⁡(k,a,κ)在键k的服务状态上执行a, 把结果交给κ; Provide⁡(k,s,P)以初始状态s提供键k; Spawn⁡(c,P)注册子组件c.

这就是一个free monad, κ是延续. 键的限制写在构造子里, 所以程序只能操作它声明的依赖和它可能提供的键, 这由构造保证, 不需要另外检查; 即便κ无穷分叉, 也不必遍历它的路径. 程序是良基的 (每条路径都有限, 但路径长度未必有界), 看不到状态, 能得到的信息只有操作的结果. 名字和提供编号由规则层分配, 程序不接触.

第3章 组件, fiber与状态

演算的粒度是: 每个服务操作是一个原子步, 步与步之间都可以放弃, 任何一步都可能失败. 组件的一个实例称为fiber, 这个词沿用Cordis (取自React), 与fibration无关.

定义3.1. 一个组件是四元组 ⟨ d⊆K , p⊆K , body∈ Prog d,p ,reacts ⟩ , 分别是依赖, 可能提供的键, 启动程序, 以及事件处理器 (组件编号的列表). 组件放在状态之外的程序表prog:C→Component里, 其中C是组件编号的集合. 对c∈C, 把prog⁡(c)的四个分量记作d⁡(c),p⁡(c),body⁡(c),reacts⁡(c); 对fiber n, 记cn为它的组件 (见下一个定义), p⁡(n)指p⁡(cn), 余者类推. body的类型已经保证它只操作d∪p中的键, 只提供p中的键.

与Cordis不同, 提供的键是静态声明的. 这使得不同fiber的p两两不相交可以在插入时检查, 依赖关系是否无环也可以静态判定; 进展和合流都需要无环.

定义3.2. 状态是⟨next,F,B⟩, 其中next是新鲜名字, 提供编号和令牌共用的计数器, F:ℕ⇀Fiber是注册表, B:K⇀Binding是当前的服务绑定: Fiber ⩴ ⟨ c∈C , π∈ ℕ+ {root} , τ∈𝔹 , θ∈Θ ⟩ Binding ⩴ ⟨ pid,owner, s∈S ⟩ θ ⩴ Inactive⁡ (ζ) | Loading⁡ ( P,acc,ω ) | Active⁡ ( acc,ω ) | Unloading⁡ ( acc,ω,ζ ) u ⩴ UOp⁡ ( k,pid,tok,g ) | UProv⁡ ( k,pid ) | USpawn⁡ (m) 各部分的含义如下.
  • fiber: c是它的组件, π是父fiber (根fiber为root), τ是已请求移除标记, θ是生命周期状态.
  • 绑定: pid是提供编号 (下文记作ι), owner是提供者的名字, s是服务状态.
  • 错误: ζ是可选的错误, ζ=⊥表示没有错误, 非⊥的错误记作ξ. 具体的错误值不影响本文的结论; 规则中出现的有程序执行Fail时的EUser和键冲突时的EConflict.
  • 累加器: acc是撤销项u的列表, 表头是最近的一项.
  • 撤销项: UOp⁡(k,pid,tok,g)记下在键k上, 提供编号为pid的绑定上以令牌tok做过的操作, g是它给出的逆; UProv⁡(k,pid)记下这个fiber建立的绑定; USpawn⁡(m)记下这个fiber插入的子fiber m.
  • 视图: ω:K⇀ℕ的定义域恰为该fiber的组件的d, 记录每个依赖解析到的提供编号.

几点说明.

  • 四个生命周期状态代替Cordis的六个: FAILED就是Inactive⁡(ξ), DISPOSED就是条目不存在. 下文称θn=Inactive⁡(ξ)的fiber n 是失败的.
  • 累加器是附录A中复合给出的逆, 只是拆成撤销项的列表, 以便逐项撤销, 逐项设守卫. UOp项记下操作用的令牌, 这是恢复精确性的证明所需要的.
  • 每次Provide步建立绑定时取一个新的提供编号, 以它作为这次提供 (provision) 的身份. 提供者撤掉再重新提供时编号改变, 依赖它的fiber会重新加载, 绝不会拿着过期的绑定继续运行.
  • 绑定中的服务状态被提供者和所有依赖者共同操作, 是共享且可变的.

第5章 规则

规则写作γ⟶ℓγ′, 标签ℓ决定唯一的后继 (若存在), 所以演算就是一个确定性的函数step:State→Label→MaybeState, 其中State是状态的集合, Label是全部标签 (编排标签与生命周期标签) 的集合. 选择哪个标签是调度的事, 不在演算之内. 凡是从next取名字, 编号或令牌的规则, 都随后把next加一. 规则中x←v表示把状态的这一部分改为v, 其余部分不变; x≔e则只是给e起名字x, 比如m≔next表示新fiber的名字取next的当前值. 全文中≔都表示定义, ←只用于规则和影子存储 (定义6.3.3) 对状态的更新.

规则分两类. 名字以O开头的五条是编排规则, 代表外部输入 (插入, 移除, 重置, 重启, 事件反应), 一串编排标签称为编排输入; 名字以L开头的八条加载与卸载规则合称生命周期规则, 它们的标签就是L⁡(n)中的标签, 按生命周期规则走的一步称为生命周期步. 生命周期规则由演算自己驱动, 目的是让每个fiber追上它的target.

第5.1节 编排规则

  • O-Insertc: 若p⁡(c)与所有现存fiber的p不相交 (下文简称p⁡(c)不冲突), 则以m≔next为名插入⟨c,root,false,Inactive⁡(⊥)⟩, next加一.
  • O-Disposen: 若n∈dom⁡(F), 则τn←true.
  • O-Resetn: 若θn=Inactive⁡(ξ), 则θn←Inactive⁡(⊥).
  • O-Restartn: 若θn为Loading⁡(_,acc,ω)或Active⁡(acc,ω), 且¬τn, 则θn←Unloading⁡(acc,ω,⊥).
  • O-Reactni: 若θn=Active⁡(acc,ω), ¬τn, reacts⁡(cn)的第i项为c, 且p⁡(c)不冲突, 则插入子fiber⟨c,n,false,Inactive⁡(⊥)⟩, 名为m≔next, 并令θn←Active⁡(USpawn⁡(m)::acc,ω).

O-Reset对应Cordis在失败后用update重试; O-Restart对应restart, 卸载后由L-Begin重新加载; O-React把一次事件反应建模为子fiber, 反应的操作就是子fiber的操作, 构成一个运行期效应, 单独撤销就是对子fiber执行O-Dispose.

第5.2节 加载

  • L-Beginn: 若θn=Inactive⁡(⊥)且target⁡(n)=ω≠⊥, 则θn←Loading⁡(body⁡(cn),[],ω).
  • L-Divertn: 若θn=Loading⁡(P,acc,ω)且target⁡(n)≠ω, 则θn←Unloading⁡(acc,ω,⊥).
  • L-Stepn: 若θn=Loading⁡(P,acc,ω)且target⁡(n)=ω, 则按P分情况:
    • Done: θn←Active⁡(acc,ω);
    • Fail: θn←Unloading⁡(acc,ω,EUser);
    • Call⁡(k,a,κ): 若k∈d⁡(cn), 查视图ω; 否则查当前绑定B (owner必须是n). 得到编号ι; 取令牌t≔next, 在该绑定的状态s上运行runats. 失败则进入Unloading并带错误; 成功得到(s′,g,o)时写回s′, 并令θn←Loading⁡(κ⁡(o),UOp⁡(k,ι,t,g)::acc,ω). 解析失败视为失败;
    • Provide⁡(k,s,P′): 要求k∈p⁡(cn)且B⁡(k)未定义; 以ι≔next为编号令B⁡(k)←⟨ι,n,s⟩, θn←Loading⁡(P′,UProv⁡(k,ι)::acc,ω). 要求不满足时进入Unloading并带错误EConflict;
    • Spawn⁡(c,P′): 要求p⁡(c)不冲突; 插入子fiber⟨c,n,false,Inactive⁡(⊥)⟩, 名为m≔next, 并令θn←Loading⁡(P′,USpawn⁡(m)::acc,ω). 冲突时进入Unloading并带错误EConflict.

所以L-Step在target⁡(n)=ω时总是适用的, Loading的fiber不会卡住. 键k同时在d和p中时以依赖为准, 查视图. 这样的组件提供k时, k已经由它依赖的提供者绑定, 所以必然冲突; 并且它在自己之上 (c≺c, ≺见定义6.4.1), 违反定义6.7.2中的有秩. 所以满足义务的组件表中d与p不相交.

第5.3节 卸载

  • L-Leaven: 若θn=Active⁡(acc,ω)且target⁡(n)≠ω, 则θn←Unloading⁡(acc,ω,⊥).
  • L-Undon: 若θn=Unloading⁡(u::acc,ω,ζ)且下面按u分的前提成立, 则θn←Unloading⁡(acc,ω,ζ), 并且:
    • UOp⁡(k,ι,t,g): 若绑定ι仍在, 把它的状态s改为g⁡(s);
    • UProv⁡(k,ι): 守卫, 没有m≠n满足resolves⁡(m,ι); 删除B⁡(k);
    • USpawn⁡(m): 要求m∉dom⁡(F), 即子fiber已被移除.
  • L-RetireChildn: 若θn=Unloading⁡(USpawn⁡(m)::_,_,_), m∈dom⁡(F)且¬τm, 则τm←true.
  • L-Unloadedn: 若θn=Unloading⁡([],ω,ζ), 则θn←Inactive⁡(ζ).
  • L-Removen: 若τn, θn=Inactive⁡(_), 且没有m满足πm=n, 则删除F⁡(n).

于是父fiber按LIFO撤到USpawn⁡(m)时, 先请求子fiber退出, 然后等它卸载并被移除, 再继续撤销更早的项; 在spawn之后登记的效应此时已经撤销完毕. 提供者撤到UProv⁡(k,ι)时, 要等所有解析到ι的依赖者先卸载. 这两处是演算中仅有的等待.

第5.4节 设计决定

主要的设计决定如下, 与论文的差别见附录C.

  • 移除: 只有一个外部请求O-Dispose, 条目在已请求移除, 已Inactive, 没有子fiber时由L-Remove自动删除. 外部不必等待卸载完成再发第二个请求, 条目也不会在子fiber还在时被删掉.
  • 卸载逐项进行: 累加器逐项撤销, 这样守卫才能精确到每次提供, USpawn才能等待子fiber.
  • LIFO串行: Cordis用Promise.all并发执行disposer. 后登记的效应往往依赖先登记的, LIFO不需要任何额外假设就是对的.
  • 放弃加载: 每个服务操作是原子步, 步与步之间都可以L-Divert. JS的await只出现在操作之间, 所以没有需要落地的在途操作.
  • 失败之后: 失败的fiber停在Inactive⁡(ξ), 由外部用O-Reset决定是否重试.
  • 运行期效应: 不把累加器改成树, 而是用O-React把反应编码为子fiber. 子fiber本身就是一棵子效应树.
  • 隔离与可用性检查: 不加规则. 键是服务名加作用域标签, 隔离就是对组件表做键重命名, 见第6.6节; 在提供时求值的检查是程序自己就能做的判断.

第6章 元理论

这一章陈述演算的性质: 良构性被保持, 依赖顺序被遵守, 卸载精确地撤销效应, 系统不会死锁且会终止, 以及终态与执行顺序无关. 最后一节把它们汇总为一个定理.

本章频繁使用第3章和第4章的记号, 先回顾一下.

  • 状态是⟨next,F,B⟩. next是名字, 提供编号和令牌共用的计数器. F是注册表, F⁡(n)=⟨cn,πn,τn,θn⟩依次是fiber n 的组件, 父fiber, 已请求移除标记和生命周期状态; θn为Loading, Active或Unloading时, 其中的视图记作ωn, 它把n的每个依赖映到所解析的提供编号.
  • B是当前的服务绑定. B⁡(k)有定义时形如⟨ι,o,s⟩, 表示键k此刻由fiber o 提供, 这次提供的编号是ι, 提供者和依赖者共享的服务状态是s; 无定义表示此刻没有fiber提供k. 绑定由Provide步建立, 在提供者撤销UProv⁡(k,ι)时删除.
  • 累加器中的撤销项有三种: UOp⁡(k,ι,t,g) (在编号为ι的绑定上以令牌t做过的操作, 逆为g), UProv⁡(k,ι) (这个fiber建立的绑定), USpawn⁡(m) (这个fiber插入的子fiber m).
  • θn=Inactive⁡(ξ) (ξ≠⊥) 的fiber是失败的; installed⁡(n)指n不处于Inactive; resolves⁡(m,ι)指已安装的m的视图中有编号ι; target⁡(n)是n此刻应有的视图, 为⊥表示n不该运行; L⁡(n)是n上的八种生命周期标签.

第6.1节 保持性

定理6.1.1. 不变式WF在初始状态成立, 并被每条规则保持. 它由以下几条组成:
  • 现存名字, 编号, USpawn中的子名字都小于next;
  • 子fiber的父fiber存在, 已安装, 且累加器中有对应的USpawn;
  • 现存fiber的p两两不相交;
  • 已解析的每个依赖都有绑定, 编号与视图一致, owner不是自己;
  • 已安装fiber的视图的键序列恰为d;
  • 每个绑定的owner存在, 已安装, k∈p⁡(owner), 且owner的累加器中有对应的UProv;
  • 累加器中的每个UProv⁡(k,ι)都对应一个现存绑定, 编号为ι, owner为自己;
  • 一个累加器中每个键至多有一个UProv.
证明. 对规则逐条检查. 有意思的情形如下.
  • O-Insert, O-React和Spawn步都检查新组件的p与现存fiber不冲突, 所以不相交性保持.
  • Provide步要求k∈p⁡(cn)且B⁡(k)未定义, 并同时在累加器里压入UProv, 所以绑定与累加器的对应保持.
  • 撤销UProv时守卫保证没有其他已安装fiber解析到这个编号, 所以删除绑定不会破坏已解析的依赖都有绑定.
  • L-Remove要求没有子fiber, 所以父fiber存在的条件保持.
  • L-Begin取的视图就是target, 它的键序列恰为d, 并且只解析到Active的提供者.
◻

推论: 有子fiber或绑定的fiber一定已安装; 一个fiber卸载完毕时, 它的子fiber和绑定都已经不存在了.

第6.3节 恢复精确性

定义6.3.1. 称(a,ta)对(b,tb)撤销独立, 记作RevertIndep⁡(a,ta,b,tb), 如果对a可能给出的每个逆g
  1. 对每个x, runbtbx与runbtbg⁡(x)都是None; 或者runbtbx=(x1,h1,o), runbtbg⁡(x)=(x2,h2,o), 其中x2≃g⁡(x1)且∀y.h2⁡(y)≃h1⁡(y);
  2. 对b可能给出的每个逆h, ∀x.g⁡(h⁡(x))≃h⁡(g⁡(x)).
第一条说b不在乎a的效应是否已被撤掉, 第二条说两者的逆可以交换.

撤销独立正是撤掉a的效应而让b的效应留着所需要的条件; 它不要求a和b本身可交换 (先a后b与先b后a结果相同). 下面的引理在单个绑定上说明这一点.

引理6.3.2. 设a带见证且runats0=(s1,g,o). 设τ是一串其他fiber的步骤 (它们的操作, 以及它们撤销时施加的逆), 每一步都与g相容 (即满足定义6.3.1中相应的一条), 记exec⁡(τ,s)为从s出发执行τ所到达的状态. 那么 g⁡ ( exec⁡ ( τ, s1 ) ) ≃ exec⁡ ( τ, s0 ) , 并且τ中其他fiber的操作在两次执行中得到相同的结果. 换言之, 在终点撤销a, 等于a从来没有执行过.
证明. 记实际执行的状态为x, 不执行a的执行的状态为y, 对步骤归纳证明g⁡(x)≃y并且两边其他fiber的操作看到相同的结果.
  • 起点: g⁡(s1)≃s0是a的见证条件.
  • 其他fiber的操作b: 相容性说b在x和g⁡(x)上同时失败或同时成功, 后者的后继≃前者的后继再施g, 结果相同; 再由b尊重≃, 把g⁡(x)换成y也一样.
  • 其他fiber撤销时施加的逆h: g⁡(h⁡(x))≃h⁡(g⁡(x))≃h⁡(y), 第一步是相容性, 第二步是h尊重≃.
◻
定义6.3.3. 对状态γ, 记store⁡(γ)为它的存储: store⁡(γ)⁡(k)=s当键k当前绑定的服务状态为s, 即B⁡(k)=⟨_,_,s⟩, B⁡(k)无定义时store⁡(γ)⁡(k)也无定义. 称n在γ中有待撤销操作, 如果n在γ中存在, 处于Loading, Active或Unloading, 并且它的累加器中有UOp项, 即它对服务状态做过, 但还没有撤销的操作; n不存在, 或处于Inactive (尚未加载或已卸载完毕) 时, 它没有待撤销操作. 设γ0⟶⁎γ是一次执行, n是一个名字. 沿这次执行对n定义影子存储σ^: 起点处σ^←store⁡(γ0), 此后每一步按它对绑定所做的事更新:
  • 某个fiber m 的L-Step在键k上以令牌t成功运行了a: 若m=n, σ^不变; 否则把σ^⁡(k)换成runatσ^⁡(k)的后继;
  • 某个fiber m 的L-Step在键k上运行a失败: σ^不变. 在定理6.3.5的假设下, 操作在影子上失败当且仅当它在实际执行中失败 (见那里的证明), 所以影子不需要单独处理实际成功而影子失败的情形;
  • 某个fiber m 撤销UOp⁡(k,ι,t,g)并作用于现存的绑定: 若m=n, σ^不变; 否则把σ^⁡(k)换成g⁡(σ^⁡(k));
  • Provide步以初始状态s建立键k的绑定: 令σ^⁡(k)←s; 撤销UProv⁡(k,ι)删除绑定: 令σ^⁡(k)无定义. 这两条对所有fiber都照常进行, 包括n;
  • 其余的步不改动σ^.
所以影子跳过的只是n自己的服务操作和它们的撤销, 不是n的存在: n的提供照样建立和删除, 其他fiber照样解析到它.
定义6.3.4. 记opsk⁡(P)为程序P中对键k的操作之集, 即在P的某条路径上以Call⁡(k,a,κ)的形式出现的a之集. 称(a,b)在键k上可能相遇, 记作meetk⁡(a,b), 如果存在组件c和c′, 使得a作为对k的操作出现在body⁡(c)中, b出现在body⁡(c′)中, 并且当c=c′时c不提供任何键: meetk ⁡ ( a,b ) :⇔ ∃ c, c′ . a∈ opsk ⁡ ( body⁡ (c) ) ∧ b∈ opsk ⁡ ( body⁡ ( c′ ) ) ∧ ( c= c′ ⇒ p⁡ (c) =∅ ) . 假设(H)是: 可能相遇的操作对在不同令牌下撤销独立, meetk ⁡ ( a,b ) ∧ ta ≠ tb ⇒ RevertIndep⁡ ( a, ta ,b, tb ) . 定义中的蕴涵是说: 同一组件的两个操作, 只在该组件不提供任何键时才算可能相遇. 提供键的组件同时至多有一个实例 (各fiber的p两两不相交), 它的两个操作来自同一个fiber, 按LIFO撤销, 不需要假设.
定理6.3.5. 设所有服务操作良好, 且(H)成立. 设γ0满足不变式和下面证明中的辅助不变式 (两者在每个可达状态都成立), n在其中没有待撤销操作, γ0⟶⁎γ是一次执行, σ^是沿这次执行对n得到的影子存储 (定义6.3.3), 并且n在γ中也没有待撤销操作 (比如卸载完毕). 那么对每个键k, store⁡(γ)⁡(k)与σ^⁡(k)同时无定义, 或者 store⁡ (γ) ⁡ (k) ≃ σ^ ⁡ (k) . 换言之, 卸载n的结果, 就是同一次执行中略去n全部操作所得的结果, 不论其他fiber同时做了什么.
证明. 对键k, 设它当前的绑定为B⁡(k)=⟨ι,_,s⟩ (编号ι, 服务状态s), 记pendk为n的累加器中所有UOp⁡(k,ι,_,g)项的g组成的列表, 最近的在前, 并记pendk⁡(s)为把它们依次 (最近的先) 作用于s的结果. 沿执行维护两个不变式.
  1. 主不变式: 对每个键k, B⁡(k)与σ^⁡(k)同时无定义, 或者pendk⁡(s)≃σ^⁡(k).
  2. 辅助不变式: 每个fiber m 的每个待撤销项UOp⁡(k,ι,t,g)都来自m的组件的程序中对k的某个操作a, 即g是(a,t)给出的逆; 其中t<next, 并且不同fiber的撤销项所用的令牌互不相同.
辅助不变式由规则直接保持: 令牌取自next, 每取一次next加一. 它的作用是在下面的情形中让(H)适用: n的待撤销项中的g来自n的组件的程序中的某个a; 若另一个fiber在k上运行b, 则b出现在它的组件的程序中; 若另一个fiber撤销它的一项h, 则由辅助不变式, h是它的组件的程序中某个b给出的逆. 两种情形都有meetk⁡(a,b), 且两者令牌不同. 起点处n没有待撤销操作, 每个pendk都是空列表, 主不变式就是σ^=store⁡(γ0). 逐类检查步骤:
  • n自己的操作: 把状态从s改为s′, 并压入逆g. 因为g⁡(s′)≃s, 先施新压入的逆就回到原来的情形, 而影子不动.
  • n撤销一项: 实际状态施加了这个逆, 待撤销的列表少了这一项, 两边的作用抵消.
  • 其他fiber在同一绑定上以令牌tb执行操作b: 实际状态s变为b在s上的后继, 影子σ^⁡(k)≃pendk⁡(s)也执行b. 需要比较b在s上和在pendk⁡(s)上的运行. 对pendk中的每个g, 由辅助不变式和(H), 撤销独立的第一条成立; 对列表的长度归纳, 第一条对整个复合pendk也成立: 每用一次, b两边给出的结果相同, 给出的逆逐点≃, 所以可以接着用下一个. 于是b在s上和在pendk⁡(s)上同时失败或同时成功, 成功时若b在s上的后继为s′, 则它在pendk⁡(s)上的后继≃pendk⁡(s′); 再由b尊重≃, 把pendk⁡(s)换成影子也一样. 失败时实际的fiber进入Unloading, 绑定不变, 影子也不变 (定义6.3.3); 成功时主不变式在新状态上成立.
  • 其他fiber的撤销项h: 两边都施加h. 对pendk中的每个g, 由辅助不变式和(H), 撤销独立的第二条给出∀y.g⁡(h⁡(y))≃h⁡(g⁡(y)); 同样对列表长度归纳, 得到pendk⁡(h⁡(s))≃h⁡(pendk⁡(s)), 再由h尊重≃得到主不变式.
  • 绑定的创建与删除: 在两边同时发生; n仍有待撤销操作的绑定不会被删除, 这由守卫保证.
最后n没有待撤销操作时, 每个pendk都是空列表, 主不变式说的就是实际存储≃影子存储.
◻

这里比较的是同一次执行, 不是n从未存在的另一次执行. 影子中n的提供照样存在过, 因它而加载的依赖者和它spawn的子fiber照样运行过, 并且由引理6.3.2, 其他fiber的操作在实际执行和影子中得到相同的结果, 所以它们走的是同一条路径. 若n从未存在, 这些依赖者根本不会加载, 调度也可能完全不同, 本定理对那样的执行不作断言. 依赖者自己的操作并不包括在n的操作之中; 在n撤销提供之前它们已经卸载, 它们的操作由它们各自的卸载撤销, 对每个依赖者分别应用本定理即可.

推论6.3.6. 运行期效应的撤销也是精确的: 从效应出现之前到它的子fiber被移除之后, 每个绑定的状态都≃略去该效应全部操作所得的状态.
证明. 取n为O-React插入的子fiber, γ0为插入之前的状态, γ为它被移除之后的状态. n在γ0和γ中都不存在, 所以都没有待撤销操作, 由定理6.3.5即得.
◻

注意这里只要求可能相遇的操作对撤销独立, 不要求操作本身可交换 (定义6.5.1); 同一fiber内部的操作按LIFO撤销, 不需要任何假设.

第6.4节 进展与终止

定义6.4.1. 称c′在c之上, 记作c≺c′, 如果 p⁡ (c) ∩ d⁡ ( c′ ) ≠∅ , 或者c可能spawn c′, 即c′出现在c的程序的某个spawn中, 或是c的事件处理器. 称r:C→ℕ是以M为界的秩, 如果 c≺ c′ ⇒ r⁡ (c) < r⁡ ( c′ ) <M . 一个状态是稳定的, 记作settled⁡(γ), 如果每个fiber n满足下列之一: { θn = Inactive⁡ (ξ) ∧ ¬ τn , 失败并停下 θn = Inactive⁡ (⊥) ∧ ¬ τn ∧ target⁡ (n) =⊥ , 不该运行 θn = Active⁡ ( _,ω ) ∧ target⁡ (n) =ω , 该运行且视图正确 特别地, 稳定状态中没有Loading或Unloading的fiber.

所以只剩下证明静止状态中没有Unloading的fiber. 沿≺作良基归纳 (≺没有无限上升链): 设组件在cn之上的fiber都不处于Unloading, 证明n也不处于Unloading. 若n处于Unloading, 由上面的检查它只可能卡在两处之一:
  1. 撤销UProv⁡(k,ι)时, 还有已安装的m解析到ι. 这时n提供了m声明的键, 所以cn≺cm. 又n已经不是Active, ι不再可见, 所以target⁡(m)=⊥. m已安装, 若它处于Loading, L-Divert可用; 若处于Active, L-Leave可用; 所以它处于Unloading, 与归纳假设矛盾.
  2. 撤销USpawn⁡(m)时, 子fiber m 还在并且已被请求移除 (否则L-RetireChild可用). 这时cn≺cm. 若m未安装, 它没有子fiber, L-Removem可用; 若已安装, 由τm有target⁡(m)=⊥, 与前一种情形同理, m处于Unloading, 与归纳假设矛盾.
所以静止状态中没有Unloading的fiber; 结合上面的检查, 每个fiber都稳定.
◻
定理6.4.3. 设有以M为界的秩r (定义6.4.1), 并且每个程序的任一路径长度都不超过常数N. 那么从满足不变式的状态出发, 不存在无限的执行 γ0 ⟶ ℓ0 γ1 ⟶ ℓ1 ⋯ , 其中每个ℓi都是生命周期标签.
证明. 给每个fiber n 一个自然数度量μn, 它是target不变时n还能走的生命周期步数的上界. 取常数D, 使它大于一次加载和随后的卸载所需的步数 (由N和键的个数决定). 按生命周期状态:
  • Inactive⁡(ξ): 已请求移除时为1 (还剩L-Remove), 否则为0.
  • Inactive⁡(⊥): target有值时为D (还要整个加载一遍), 否则同上.
  • Loading, 视图等于target: D减去累加器的长度. 每个L-Step都压入一项或结束加载, 所以严格下降.
  • Active, 视图等于target: 0.
  • Unloading, 以及视图不等于target的Loading和Active: 累加器的权重 (每项为1, USpawn⁡(m)在子fiber还在且未请求移除时再加1, 留给L-RetireChild), 加上收尾的步数; 若卸载后还会重新加载 (没有错误且target有值), 再加D. Loading和Active的情形再加1, 留给L-Divert或L-Leave.
状态的度量是向量Φ⁡(γ), 它的第i个分量是秩为i的fiber的度量之和; 向量按字典序比较, 低秩的分量优先. 秩有界, 所以这个字典序是良基的. 设一步生命周期规则由fiber n 走出, 它的秩为i. 逐条检查规则可得:
  1. n自己的度量严格下降 (被L-Remove删除时记为0);
  2. 其他秩不超过i的fiber的度量不变. 这一步可能让秩更低的fiber的某条规则变得可用 (依赖者卸载后提供者才能撤销提供, 子fiber移除后父fiber才能撤销spawn), 但不改变它们的状态, 也就不改变它们的度量;
  3. 新出现的fiber (spawn的子fiber) 的秩高于i.
于是Φ⁡(γ)的第i个分量严格下降, 更低的分量不变, 更高的分量可能增加, 整体按字典序严格下降. 良基序上没有无限下降链, 所以没有无限的执行.

第6.5节 合流

合流分五层证明, 每层建立在前一层的基础上.

定义6.5.1. 称(a,ta)与(b,tb)可交换, 如果对每个s, 先a后b与先b后a都失败, 或都成功并给出≃相关的终态, 且a和b各自的结果相同. 恢复精确性只需要撤销独立 (定义6.3.1), 合流还需要可交换: 不同的调度会让操作以不同的顺序作用在同一个绑定上.
定义6.5.2. 称服务满足合流假设, 如果
  1. 每个操作都良好;
  2. 操作给出的逆与所在的状态无关: 若runats1=(_,g1,_), runats2=(_,g2,_), 则∀x.g1⁡(x)≃g2⁡(x);
  3. 令牌不影响后继(在≃意义下)和结果;
  4. 可能相遇的操作在不同令牌下可交换 (定义6.5.1), 并且满足撤销独立第一条的一个弱形式: 对(a,ta)给出的每个逆g, 每个x∈After⁡((a,ta)), 以及与a可能相遇的(b,tb) (tb≠ta), 若b在x上成功, 则b在g⁡(x)上也成功, 并且两次运行满足第一条中成功情形的关系. 这里After⁡((a,ta))是满足下面两条的最小状态集合:
    • (a,ta)在某个状态上成功运行的后继属于它;
    • 若w属于它, b与a可能相遇, tb≠ta, 且runbtbw成功给出后继w′, 则w′属于它.
    即a之后, 只经过与它可能相遇的其他操作所能到达的状态.
第1条已在恢复精确性中用到; 第4条中撤销独立的部分是(H)所要求的第一条的弱化 (只在After⁡((a,ta))上, 只约束b成功的情形); 第2, 3条和第4条里的可交换是合流新加的.

第2条排除了逆依赖于起点的操作, 比如引言中的把x设为5. 原因是两次执行中同一个操作可能在不同的状态上运行, 若逆随状态而变, 终态中待撤销的逆就不再是同一组. 所以状态相关的逆只对恢复精确性有意义, 合流需要的是与状态无关的逆; 按名字注册和监听器注册都属于后者. 第3条是因为令牌由调度决定, 两次执行中同一个操作拿到的令牌可能不同.

定理6.5.3. [控制层, 无spawn]: 设组件都不spawn, 有定理6.4.3中的秩r和界M,N, 并且每个组件的程序的每条到达Done的路径都提供了它可能提供的所有键. 设γ0满足不变式, γ0⟶⁎γ1和γ0⟶⁎γ2只走生命周期规则, γ1和γ2都静止且没有失败的fiber. 用Fi, Bi表示γi的注册表和绑定, cn,i, θn,i表示Fi⁡(n)的组件和生命周期状态, 则 dom⁡ ( F1 ) = dom⁡ ( F2 ) c n,1 = c n,2 θ n,1 = Active⁡ ( _,_ ) ⇔ θ n,2 = Active⁡ ( _,_ ) owner⁡ ( B1 ⁡ (k) ) = owner⁡ ( B2 ⁡ (k) ) 第二, 三式对所有n∈dom⁡(F1)成立, 第四式对所有k成立.
证明. 论证不比较两次执行的过程, 而是刻画终态. 在没有失败fiber的静止状态中, 一个fiber是Active当且仅当它没有被请求移除, 且它声明的每个键都由一个Active的fiber提供. 这里用到了关于Done路径的前提: Active的fiber提供了它可能提供的所有键. 这样, Active的fiber之集合是一个不动点方程的解, 方程只依赖起点. 沿秩归纳可知这个方程只有一个解. 秩的前提不能去掉: 若c提供k1而依赖k2, c′提供k2而依赖k1, 则两者都Active和两者都不Active都是这个方程的解.
◻
定理6.5.4. [服务状态, 无spawn]: 在上一个定理的设定下, 再设服务满足合流假设 (定义6.5.2). 则对每个键k, 若B1⁡(k)=⟨_,_,s1⟩且B2⁡(k)=⟨_,_,s2⟩, 则s1≃s2.
证明. 分三步.
  1. 在一次执行中, 每个绑定的状态≃它的初始状态再依令牌顺序执行它上面尚未撤销的操作.
  2. 每个已加载的fiber的累加器对应一条理想轨迹: 单独运行它的程序, 每个操作的回答都在它解析到的那次提供的初始状态上依次执行这个fiber自己在该键上先前的操作得到, 不计其他fiber的操作. 可能相遇的操作可交换, 所以其他fiber穿插进来的操作不改变这里看到的结果, 所以理想轨迹只由程序和初始状态决定. 沿秩归纳, 两个终态中对应的Active fiber有相同的轨迹.
  3. 于是每个键上待撤销的操作在两个终态中是同一组, 只是顺序可能不同; 由可交换性, 重排不改变终态的≃类.
◻
定理6.5.5. [带spawn]: 设定同上, 但允许组件spawn, 并且启动时spawn的子fiber不被直接O-Dispose. fiber的名字依赖于调度, 所以给每个fiber一个规范名: 根fiber保留自己的名字, 子fiber由父fiber的规范名和它在父fiber的spawn中的位置命名. 那么两个终态在重命名的意义下一致: 按规范名, fiber, 组件, 是否Active, 绑定都一一对应. 不论两个终态如何到达, 只要根fiber对应, 它们就一致.
证明. 父fiber是否spawn, spawn什么, 取决于它的操作的结果, 所以对应关系要沿秩归纳建立: 对应的fiber有相同的组件和理想轨迹, 因而spawn出对应的子fiber. 其余部分与无spawn的情形相同. 这里还需要一个不变式: Loading和Active的fiber的子fiber都还活着; 对启动时spawn的子fiber直接O-Dispose会破坏它, 见下文.
◻
定理6.5.6. [编排与生命周期交错]: 从初始状态出发, 接受相同编排输入 (以插入次序而不是名字指称根fiber), 并以任意方式穿插生命周期步的两次执行, 若都到达静止且没有失败fiber, 则在重命名意义下一致. 特别地, 终态与静态组装 (先全部插入再运行) 的结果一致.
证明. 插入得到的名字依赖于调度, 所以输入以插入次序指称根fiber. 沿执行记录一本账: 对每个插入次序, 若它没有被O-Dispose, 终态中恰有一个根fiber, 组件就是插入的那个. 早先的插入, 移除请求, 重启, 重置除了留下的根fiber之外不留痕迹. 于是两个终态的根fiber按插入次序一一对应, 再用上一个定理中不论终态如何到达, 只要根fiber对应就一致的那一半即可.
◻
定理6.5.7. [服务的组合]: 定理6.5.4, 定理6.5.5和定理6.5.6中对服务的要求恰是合流假设 (定义6.5.2), 所以它们对任何满足合流假设的服务成立. 两个满足合流假设的服务之和也满足它.
证明. 前一半是把三个定理的服务前提逐条对照. 和的状态属于两者之一, 一方的操作在另一方的状态上失败; 不同部分的操作从不作用在同一个状态上, 所以它们可交换, 也互不干扰. 同一部分的操作对按该部分的假设处理.
◻

合流不覆盖O-React, 也只允许对根fiber用O-Dispose. 原因是: 启动时spawn的子fiber若被直接O-Dispose, 父fiber在一次执行里保留原生命期, 在另一次执行里重新加载并重新spawn, 两次的终态确实不同; 这在Cordis中同样成立, 不是模型的人为限制. 保持性, 顺序, 恢复精确性, 进展, 终止都覆盖O-React.

第6.6节 派生形式

定理6.6.1. 隔离是对组件表的键重命名: 键取为服务名加作用域标签, 被隔离的子树换一个标签. 重命名保持各定理对组件的假设: 程序有界, 每条到达Done的路径提供组件可能提供的所有键, 秩的单调性, 以及独立性 (此时要对同一服务名上任意两个组件的操作成立, 因为同一组件可以在多个作用域中同时运行).

所以对任意组件表陈述的定理都直接适用于隔离, 不需要另外的规则.

第6.7节 汇总

前面各定理的假设分散在各节. 本节把它们分成两组: 服务的规格只谈服务自身和一个操作上的关系G, 不提任何程序; 组件的义务只谈组件表, 其中一条要求可能相遇的操作对落在G之内. 服务的作者对G证明规格, 插件的作者检查义务, 两者在G处对接.

定义6.7.1. 设G是操作上的二元关系. 称服务Σ相对G
  1. 可撤销, 如果每个操作在每个令牌下良好, 并且 G⁡ ( a,b ) ∧ ta ≠ tb ⇒ RevertIndep⁡ ( a, ta ,b, tb ) ;
  2. 可合流, 如果它满足合流假设 (定义6.5.2), 其中第4条的可能相遇的操作换成G相关的操作.
定义6.7.2. 称组件表prog相对G满足义务, 如果
  1. 有界: 存在N, 每个程序的任一路径长度都不超过N;
  2. 有秩: 存在以某个M为界的秩r (定义6.4.1), 即c≺c′⇒r⁡(c)<r⁡(c′)<M;
  3. 相遇受控: meetk⁡(a,b)⇒G⁡(a,b);
  4. 完整提供: 每个组件的程序的每条到达Done的路径都提供它可能提供的所有键.
称编排输入是根编排, 如果它只由O-Insert以及对根fiber (以插入次序指称) 的O-Dispose, O-Restart, O-Reset组成.
例子6.7.3. 下面三个服务说明规格的两部分之间的关系.
  1. 注册表 (例子1.3). 取G关联名字不同的两次登记, 名字不同的登记与查询, 以及任意两次查询, 两部分都满足. 相遇受控此时说的是: 可能相遇的两次登记, 以及登记与查询, 名字都不同, 在插件的层面就是不同插件不登记同名的工具. 同名的两次登记不撤销独立: 后一次在实际执行中失败, 撤掉前一次之后却会成功.
  2. 监听器注册 (例子1.4末尾). G取全关系时可合流, 但不可撤销: 设c不在列表x中, 两个fiber各注册一次c, 撤销独立的第一条要求x加上c之后≃x, 不成立. 若G只关联回调不同的注册, 两部分都满足, 这时相遇受控要求可能相遇的两次注册回调不同. 即使回调相同, 删去第一个c在这里仍然给出正确的结果, 所以撤销独立是充分条件而非必要条件.
  3. 变量存储. 状态是变量到值的映射, 逐点比较; 操作把x设为v的逆是把x改回原来的值, 也就是引言中的例子. 取G关联不同变量上的操作, 它可撤销. 但它的逆依赖于原来的值, 违反合流假设的第2条, 而这一条与G无关, 所以不论G怎样取, 它都不可合流.
前两个说明可合流推不出可撤销, 第三个说明可撤销推不出可合流.
定理6.7.4. 设组件表相对G满足有界, 有秩和相遇受控. 设γ是从初始状态经任意标签序列 (包括O-React和对子fiber的O-Dispose) 可达的状态.
  1. 安全 (不需要假设): γ满足不变式, 因而定理6.2.1的各条在γ成立.
  2. 活性: 从γ出发只走生命周期步, 没有无限的执行; 走到没有生命周期规则可用时, 状态是稳定的.
  3. 恢复 (服务可撤销): 设执行从初始状态到达γ, σ^是沿它略去fiber n全部操作所得的影子存储. 若n在γ中不存在或没有安装, 则对每个键k, store⁡(γ)⁡(k)与σ^⁡(k)同时无定义, 或者store⁡(γ)⁡(k)≃σ^⁡(k). 取n为一次反应的子fiber, 就是运行期效应的精确撤销.
  4. 合流 (服务可合流, 组件表还满足完整提供): 两次执行从初始状态出发, 接受相同的根编排输入, 以任意方式穿插生命周期步; 若都到达静止且没有失败的fiber, 则两个终态在重命名意义下一致, 并且与静态组装 (只按插入次序插入留下的组件) 到达的静止终态一致.
证明.
  1. 安全: 即定理6.1.1.
  2. 活性: 有秩给出≺上严格上升且有界的度量, 所以≺没有无限上升链; 由有界和有秩, 定理6.4.3排除无限的生命周期执行. 生命周期步的终点仍是可达状态, 若它静止, 则由定理6.4.2它是稳定的.
  3. 恢复: 即定理6.3.5, 取γ0为初始状态 (n在其中没有待撤销操作), 而n不存在或未安装时也没有待撤销操作. 所需的(H)由可撤销和相遇受控得到.
  4. 合流: 即定理6.5.6. 由相遇受控, 可合流中对G相关的操作所作的要求, 特别地包括了对可能相遇的操作的要求, 这正是合流假设 (定义6.5.2) 的第4条; 有界, 有秩和完整提供是定理6.5.3到定理6.5.6对组件的前提.
◻

几点说明.

  • 为什么分两部分. 恢复精确性要撤销独立的两条在所有状态上成立; 合流只用到第一条, 并且只在After⁡((a,ta))上, 却另外要求可交换, 逆与状态无关, 令牌无关. 由例子6.7.3, 两部分互不蕴涵.
  • 义务的粒度. 有界和完整提供是对单个组件的要求. 有秩和相遇受控是对整张组件表的要求: 前者对有限的表就是依赖与spawn关系无环, 后者在插件的层面读作不同插件不登记同名的工具这一类约定. 两者本质上是全局的, 因为它们说的是插件之间的关系.
  • 失败不是义务. 合流以两次执行都没有失败的fiber为前提. 失败可能来自Fail, 操作失败或键冲突, 取决于运行时的状态, 不是组件表的静态性质. 实际使用时的检查方式是: 静态组装一次, 看它是否无失败地到达静止; 由第4条, 任何其他调度到达的静止终态都与它一致.
  • 编排的范围. 第1到3条对任意编排成立, 包括O-React和对子fiber的O-Dispose; 只有第4条限于根编排, 原因见合流一节.
  • 隔离. 由第6.6节, 键重命名保持有界, 有秩和完整提供; 相遇受控则要对同一服务名上任意两个组件的操作成立. 满足这一点时, 本定理直接适用于隔离后的组件表.

附录A 单个组件的语义

本附录对应论文的3.1节, 以及3.3.2节中关于等价的部分. 它把一个程序解释为存储上带见证的部分效应, 从而说明一个组件单独卸载时存储在等价意义下复原, 并且演算中累加器的撤销项按LIFO复合起来就是这个效应的逆. 正文的定理不依赖本附录. 效应可能失败 (例如重复提供同一个键), 而恢复只能在某个等价关系下成立: free不会恢复malloc之前的堆布局. 下面固定一个类型Γ及其上的等价关系≈, 并记End⁡(Γ)≔Γ→Γ.

定义A.1. 定义部分效应 PEffΓ ≔ Γ→ Maybe ( Γ× End⁡ (Γ) ) , e⁡(γ)=(δ,g)给出新状态δ和这一步的逆g. 两个结果相关, 当且仅当都是None, 或者状态相关且逆逐点相关. 一个映射g尊重≈, 当且仅当x≈y⇒g⁡(x)≈g⁡(y).
定义A.2. e∈PEffΓ带见证, 当且仅当
  1. 若e⁡(γ)=(δ,g), 则g⁡(δ)≈γ;
  2. 上述g尊重≈;
  3. e本身尊重≈: 相关的输入给出相关的结果.
第一条只要求g在e被应用的那一点撤销它, 不要求g是全局的左逆. 这是论文的定义8和定义37.
定义A.3. 对于e1,e2∈PEffΓ, 定义先e2后e1的复合 ( e1 ⋄ e2 ) ⁡ (γ) ≔ let ( δ,g ) ≔ e2 ⁡ (γ) in let ( ε,h ) ≔ e1 ⁡ (δ) in ( ε, g∘h ) , 任一步为None时结果为None; 单位元是ηΓ⁡(γ)≔(γ,id). 对a:Γ→Maybe(Γ×End⁡(Γ)×Out)和κ:Out→PEffΓ, 按结果绑定为 bind⁡ ( a,κ ) ⁡ (γ) ≔ let ( δ,g,o ) ≔ a⁡ (γ) in let ( ε,h ) ≔ κ⁡ ( o⁡ (δ) ) in ( ε, g∘h ) . 这就是幺半群(End⁡(Γ),∘)上的writer monad (再叠一层Maybe) 的Kleisli复合: 日志是逆, 新的一项接在右边, 撤销时最先施加. 按结果绑定是论文的式(36): 每一段执行一个操作, 再根据结果选择后续.
定理A.4. 若e1, e2带见证, 则e1⋄e2带见证; 若a的前两个分量带见证, a在相关的输入上给出相同的结果o, 且每个κ⁡(o)带见证, 则bind⁡(a,κ)带见证. 特别地, 依次执行带见证的e1,…,en之后, 按LIFO顺序施加它们各自给出的逆, 回到的状态≈起点, 不需要任何关于效应之间关系的假设. 这是论文的定理10, 11, 16.
证明.
  • 复合: 逐条检查定义A.2的三个条件.
    1. 见证条件: 若e2⁡(γ)=(δ,g), e1⁡(δ)=(ε,h), 则g⁡(h⁡(ε))≈g⁡(δ)≈γ, 第一步要求g尊重≈;
    2. 复合的逆是尊重≈的映射的复合, 仍然尊重≈;
    3. 复合本身尊重≈, 因为相关的输入在每一段都给出相关的结果.
  • 按结果绑定: 相关的输入给出相同的结果, 所以选择的是同一个后续, 论证与复合相同.
  • LIFO: 对n归纳使用复合的情形, en⋄⋯⋄e1给出的逆正是g1∘⋯∘gn.
◻

论文3.1节的其余构造, 即扭曲复合, 效应上下文与track/recover, 提升effect, 以及效应的独立性与任意顺序的撤销, 本文都不需要. 演算的累加器是撤销项的列表, 按LIFO逐项撤销 (第3章); 撤销与其他fiber的交错由操作级的假设处理 (第6.3节).

附录B 观察等价

服务的≃应该取什么? 论文的回答是: 观察者只能运行操作并读取结果, 两个状态相关当且仅当没有观察者能区分它们.

定义B.1. 一个测试是字母的有限序列. 字母或者是LF⁡(a,t), 运行操作并记录结果 (操作失败则整个测试无定义); 或者是LI⁡(g), 施加某个操作可能给出的逆g. 记runTest⁡(w,s)为测试w在s上记录的结果序列 (无定义时为None). 定义不可区分 s∼ s′ :⇔ ∀w. runTest⁡ ( w,s ) = runTest⁡ ( w, s′ ) . 一个等价关系R可容许, 当且仅当每个操作都尊重它 (即R⁡(s,s′)时, runats与runats′同为None, 或给出R相关的后继和相同的结果), 并且每个可能给出的逆g都满足R⁡(x,y)⇒R⁡(g⁡(x),g⁡(y)).
定理B.2. ∼是可容许的, 并且对每个可容许的R有R⊆∼. 换言之, ∼是操作所尊重的最粗的等价关系. 特别地, 操作良好的服务有≃⊆∼.
证明. 可容许: 设s与s′不可区分. 只有一个字母LF⁡(a,t)的测试说明a在两者上同时失败或同时成功, 且结果相同; 在一个测试前面加上这个字母仍是测试, 所以两个后继也不可区分. 逆字母同理. 包含: 设R可容许, R⁡(s,s′). 对测试的长度归纳: 每个字母都把R相关的状态送到R相关的状态, 并给出相同的结果, 所以整个测试在两边的结果相同.
◻

这就是最大互模拟: 测试每走一个字母, 两边同时走一步, 比较定义性与结果.

定理B.3. 在带分发的有序事件总线上, 设c1≠c2是两个回调, 分别用令牌t1≠t2注册; 从同一状态出发, 记s12为先注册c1再注册c2所得的状态, s21为相反顺序所得的状态. 则对每个可容许的R, ¬R⁡(s12,s21). 换言之, 不论取哪个可容许的等价关系, 两次注册都不可交换.
证明. 设两种顺序得到的状态被某个可容许的等价关系联系起来. 由上一个定理, 它们不可区分. 但只含一个分发字母的测试按注册顺序返回回调的列表, 两种顺序给出的列表不同, 矛盾.
◻

分发会暴露注册的顺序. 所以要让注册可交换, 只能像例子1.4末尾那样去掉分发, 改用监听器注册; 这是被迫的, 而不是随意的选择.
