第1章 引言

会话类型和邮箱类型都是行为类型的例子. 这个短语并没有精确的形式定义; 它是一种启发式的说法, 用来描述那些目的不止于检查普通数据形状的类型系统. 一个行为类型描述了程序如何行为的某个方面. 在会话类型以及其余的讲座中, 我们关注的行为是通信.

会话类型的核心思想是把一个通信协议表达为一个类型. 这一讲所考虑的协议是双向, 点对点信道上的协议. 一个信道有两个端点, 而一个端点处的类型描述了该端点的拥有者所必须执行的通信动作的序列. 于是, 静态类型检查就能在程序运行之前验证程序中面向通信的部分.

邮箱类型 (在课程稍后出现) 处理的是另一种通信模型: 演员模型. 在那种设定下, 每个演员都有一个邮箱, 许多进程都可以向它发送消息, 而接收者一般不能依赖于消息以某种特定的顺序送达.

第2章 作为协议的会话类型: 启发性的例子

第一个例子是协议发送一个整数, 然后关闭信道. 它的会话类型是 !int. end! 构造子!int.表示下一个动作是输出一个整数; 点表示顺序; 而end!表示这个端点将关闭信道. 还有一个对偶的协议: 接收一个整数, 然后等待另一个端点关闭信道, ?int. end? 这两种终止形式都是会话类型. 其区别并不在于一个端点已经结束而另一个没有; 相反, 结束本身就是一个同步动作. 一个端点执行关闭, 另一个端点则等待这个关闭.

协议可以涉及多条消息, 并且可以改变方向. 例如, !int. !int. ?int. end! 描述了一个端点, 它发送两个整数, 接收一个整数, 然后关闭.

会话类型记录了每条消息的方向和类型, 但不记录数据值之间的语义关系. 如果一个客户端发送两个整数并期望得到它们的积或和作为回应, 那么普通的会话类型本身并不表达这一算术规约.

协议还可以包含选择. 一个简单的数学服务器可能提供加法或取反: S= & { plus: ?int. ?int. !int. end? , neg: ?int. !int. end? } 外部选择构造子&{⋯}意味着由环境通过发送一个标签来选择一个分支. 然后, 服务器遵循附着于该标签的协议. 对偶的客户端类型使用内部选择: T= ⊕ { plus: !int. !int. ?int. end! , neg: !int. ?int. end! } 这里由客户端选择分支, 并把所选的标签发送给服务器. 在这些例子中, 是客户端关闭信道而服务器等待, 但这一约定并不是数学所强制的; 重要的一点是两个端点使用了对偶的终止动作.

现实中的服务常常需要反复运行. 我们可以用方程 S= & { plus: ?int. ?int. !int.S , neg: ?int. !int.S , quit: end? } 来描述数学服务器的一个递归版本. 对应的客户端类型可以通过对选择, 方向和终止取对偶而得到: T= ⊕ { plus: !int. !int. ?int.T , neg: !int. ?int.T , quit: end! } 这一讲主体部分所建立的形式系统集中于有穷行为, 但对于这种形式的服务而言, 递归类型是所需的自然扩展.

消息不必是普通的数据. 它们本身可以是信道, 在这种情况下, 它们的消息类型是另一个会话类型. 例如, ! ( ?int. end? ) . end! 意味着: 发送一个信道端点, 其未来的行为是接收一个整数并等待关闭, 然后关闭原来的信道. 这种对于信道的传递被称为委托. 一个端点的拥有者可以运行协议的一部分, 然后把该协议其余部分的责任转交给另一个进程. 注意, 对外层协议取对偶并不会对所发送消息的类型取对偶: ? ( ?int. end? ) . end? 接收者得到的信道端点恰好具有发送者所发送的类型.

第3章 通信模型与所有权

这一讲的通信模型是并发或分布式的点对点通信. 一个进程可以使用许多信道, 但每个信道都恰好有两个端点.

信道是双向的: 任意一个端点都可以发送或接收, 这取决于协议当前所处的位置. 我们假定通信是可靠的, 并且在某个特定信道上发送的消息以相同的顺序被接收.

同一个信道中的消息顺序得到保持, 正是这一点使得会话类型的顺序结构有意义. 然而, 不同信道中的消息顺序仍然是相互独立的.

讲座中的操作性表述使用同步通信: 一次发送和对应的接收同时发生, 发送者会阻塞直到接收者就绪. 会话类型的异步版本也是可能的, 并且它更接近于基于套接字和缓冲区的实现模型, 但它需要更复杂的操作语义. 主要的定型思想在同步的设定下就已经可以看到.

一条核心的纪律是端点的唯一所有权. 如果两个进程可以随意共享同一个端点, 它们的动作就可能相互干扰. 例如, 一个类型可能说只发送一个整数, 但共享该端点的两个线程可能都试图发送. 基本的会话类型系统通过使用线性类型论中的技术来防止这种情况: 信道端点是一种资源, 它在同一时刻必须只属于一个线程. 委托遵守这一纪律, 因为发送一个端点就转移了所有权; 发送者的后续不能再使用它已经发送出去的端点.

主要的安全性保证是不存在通信失配. 如果一个端点发送一条消息, 那么另一个端点已准备好接收一条类型正确的消息; 反过来, 如果一个端点正在等待接收, 那么另一个端点已准备好发送所期望的那种消息. 会话类型的安全性所保证的另一个性质是会话保真性: 运行时观察到的消息的顺序和类型与静态地指派的会话类型相吻合.

第4章 会话类型简史

会话类型最初的一系列工作始于本田耕平 (Kohei Honda) 的CONCUR 1993论文Types for Dyadic Interaction, 随后是与竹内格 (Kaku Takeuchi) 和久保誠 (Makoto Kubo) 合作的PARLE 1994论文, 以及与Vasco Vasconcelos和久保誠合作的ESOP 1998论文. 这些论文引入了对结构化的通信协议进行定型的想法, 起初是在进程演算的设定下, 然后逐渐转向编程语言原语.

Simon Gay (本讲的讲者) 把他与Malcolm Hole合作的ESOP 1999论文Types and Subtypes for Client-Server Interactions描述为第一篇出自最初那个研究组之外的会话类型论文. 这项工作贡献了子类型, 对信道两个端点的仔细区分, 以及使用线性定型的思想来强制信道端点的唯一所有权. 它显然也是第一篇使用会话类型这个短语本身的论文: 更早的论文谈到了会话和类型, 但还没有使用这个如今已成为标准的名字.

后来的发展包括将会话类型与函数式编程相结合的工作, 用于两个以上参与者的协议的多方会话类型, 以及会话类型与线性逻辑之间的Curry-Howard对应. 前三讲的参考资料是Simon Gay和Vasco Vasconcelos最近出版的书.

第5章 用于会话的π演算

这一讲为一个小型的π演算给出会话定型. 从一个无类型的进程语言出发是有用的, 因为这样我们就可以直接定义运行时错误, 并证明良类型的进程永远不会到达这些错误. 对于有穷行为, 进程的语法是 P ⩴ 0 无动作 | x?.P 等待关闭 | x!.P 关闭 | x?y.P 接收 | x!y.P 发送 | P|P 并行复合 | ( νxy ) P 作用域限制

进程0意味着该进程已经终止. 进程x?.P等待x的另一个端点关闭, 然后作为P继续; x!.P关闭x, 然后作为P继续. 进程x?y.P在x上接收一条消息, 将其绑定到y, 然后作为P继续. 进程x!y.P在x上发送y, 然后作为P继续. 并行复合P|Q并发地运行P和Q. 最后, (νxy)P创建一个私有信道, 其两个端点是x和y, 作用域为P. 这个双重约束子是有意地不按标准来的: 它使两个端点变得显式. 也有其他约束两个端点的方式, 例如(νx+x−)P. 但事实证明, 对于会话类型而言, 双重约束子更容易处理.

进程是在结构同余的意义下考虑的. 讲座中所使用的主要的结构同余规则有: P|Q ≡ Q|P (C-Comm) ( P|Q ) |M ≡ P| ( Q|M ) (C-Assoc) P|0 ≡P (C-Neut) ( νxy ) ( P|Q ) ≡ ( νxy ) P |Q (C-Scope) ( νxy ) P ≡ ( νyx ) P (C-SwapC) ( νxy ) ( νzw ) P ≡ ( νzw ) ( νxy ) P (C-SwapB)

还有一些同余规则说的是结构同余被进程构造子所保持, 例如: 0≡0 (C-Inact) P≡Q ( νxy ) P ≡ ( νxy ) Q (C-Res) 并行复合是可交换的和可结合的, 0是它的单位元, 并且在保持约束名字新鲜的情况下, 限制可以被重新排序或向外移动. 这使得归约可以忽略无关的句法顺序, 并把潜在的通信伙伴放到一起.

两条主要的归约规则是关闭/等待交互和消息传递: ( νxy ) ( x!.P | y?.Q ) → ( νxy ) ( P|Q ) 以及, 示意性地, ( νxy ) ( x!v.P | y?z.Q ) → ( νxy ) ( P| Q [ v/z ] ) . 还有一些上下文规则, 允许在并行复合和限制的内部进行归约, 以及一条结构规则, 允许在通过结构同余重新排列之后进行归约. 选择增加了两种进程形式: x▷ { li : Pi } i∈I 和 x◁l.P . 前者提供了一个对带标签分支的外部选择; 后者选取这些标签中的一个. 当所提供的标签和所选取的标签一致时, 归约规则选择相匹配的分支.

作为一个例子, 一个一次性的数学服务器可以如下与一个客户端相连接: ( νxy ) ( x▷ { plus: x?a. x?b. x! ( a+b ) . x?.0 , neg: x?a. x! ( −a ) . x?.0 } | y◁plus. y!2. y!3. y?u. y!. P⁡ (u) ). 客户端选取plus, 发送2和3, 接收5, 关闭信道, 然后作为P⁡(5)继续, 这里假定算术表达式以所期望的方式被求值.

第6章 运行时错误与死锁

这个类型系统旨在排除通信失配. 典型的坏格局包括: 接收面对选取, 接收面对关闭, 两个接收相互面对, 或者一个分支提供某个标签, 而另一个端点选取了另一个不同的标签: × ( νxy ) ( x?z.P | y◁l.Q ) , × ( νxy ) ( x?z.P | y!.0 ) , × ( νxy ) ( x?z.P | y?w.Q ) , × ( νxy ) ( x▷ { l:P } | y◁k.0 ) ( k≠l ) .

为了形式地定义这一点, 讲座引入了前缀进程: 其第一个动作是接收, 发送, 分支, 选取, 等待或关闭的进程. 这样一个前缀的主体是第一个动作发生于其上的端点.

每个进程都结构同余于一个典范形式 ( ν x1 y1 ) ⋯ ( ν xn yn ) ( P1 |⋯| Pm ) , 其中诸Pi是前缀, 或者在没有前缀时是0. 一个可约式是位于相对端点上的一对能够通信的前缀: 等待与关闭, 接收与发送, 或者选取与包含所选标签的分支. 一个运行时错误是这样的典范形式, 它包含位于同一个受限信道的相对端点上的前缀, 而它们并不构成一个可约式.

还有其他种类的进程, 即死锁和自阻塞, 它们不符合运行时错误的定义, 超出了基本会话类型的安全性保证的范围. 死锁指的是循环依赖, 例如 ( ν x1 y1 ) ( ν x2 y2 ) ( x1 ? z1 . x2 ? z2 . x1 ?. x2 ?.0 | y2 ! v1 . y1 ! v2 . y1 !. y2 !.0 ) 自阻塞发生于接收和发送在同一个进程中被顺序排列的时候 ( νxy ) x?z. y!v. x?. y!.0 因此, 基本会话类型中所证明的安全性定理并不是最强意义上的良类型的程序总是能够取得进展. 它是一个更具体的断言, 即良类型的程序不会到达刚才所描述的通信失配. 也有Wen Kokke等人的工作[1], 把死锁也加入到会话类型所要避免的行为之中.

第7章 类型, 对偶与定型规则

对于有穷演算, 会话类型的语法是 T ⩴ end? 等待关闭 | end! 关闭 | ?T.U 输入一个类型为T的值, 然后表现得如同U | !T.U 输出一个类型为T的值, 然后表现得如同U | & { li : Ti } i∈I 外部选择 | ⊕ { li : Ti } i∈I 内部选择

与线程的对偶类似, 对偶也出现在会话类型之中. 对偶关联起那些可以安全地出现在一个信道的两个端点处的类型. 关闭与等待对偶, 输入与具有相同消息类型的输出对偶, 而外部选择与具有相匹配的标签和对偶的后续的内部选择对偶. 等价地, 对于非递归类型: end? ⊥ = end! , end! ⊥ = end? , ( ?T.U ) ⊥ = !T. U⊥ , ( !T.U ) ⊥ = ?T. U⊥ , ( & { li : Ti } i∈I ) ⊥ = ⊕ { li : Ti ⊥ } i∈I , ( ⊕ { li : Ti } i∈I ) ⊥ = & { li : Ti ⊥ } i∈I . {译注: 原文此处写作(?T.U)⊥=!T.U和(!T.U)⊥=?T.U, 漏掉了后续U上的对偶, 这里已改正. 参见前文中递归的数学服务器的客户端类型.} 对于递归类型, 对偶通常更适合以余归纳的方式表述.

定型判断具有形式 Γ⊢P , 其中Γ将变量映射到会话类型. 一个进程本身并不被指派类型; 相反, 它是对照它所使用的资源而被检查的. 在基本系统中, 环境Γ恰好包含P的自由端点.
