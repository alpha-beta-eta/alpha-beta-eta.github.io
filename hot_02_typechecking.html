第1章 线性的意义

我们首先稍微探索一下线性定型的限制. 回想一下, 判断中的每个变量x和yi在运行时都代表一个单元的地址. y1 : B1 ,…, yn : Bn ⏟ 从这里读取 ⊢ P:: ( x:A ) ⏟ 写入这里 线性保证了每个变量yi都将被使用, 并且变量x将被写入, 假设P会终止. 执行的状态由多个语义对象cellcv (其中所有的地址c都互不相同, 而v是一个小值) 以及一些代表正在运行的进程的procP组成. 如果一个格局完全由内存单元组成, 我们就到达了一个终格局. 回想一下这些规则: proc ( writecv ) ⟶ cellcv cellcv , proc ( readcK ) ⟶ proc ( v▹K ) proc ( cut ( x:A ) P⁡ (x) Q⁡ (x) ) ⟶ proc P⁡ (a) , proc Q⁡ (a) ( a 新鲜 ) cellbv , proc ( idab ) ⟶ cellav proc ( callpab ) ⟶ proc Q⁡ ( a,b ) ( procpxy = Q⁡ ( x,y ) ∈Σ ) ( ) ▹ ( ) ⇒Q = Q ( a,b ) ▹ ( x,y ) ⇒ Q⁡ ( x,y ) = Q⁡ ( a,b ) k⁡ (a) ▹ { ℓ⁡ ( yℓ ) ⇒ Qℓ ⁡ ( yℓ ) } ℓ∈L = Qk ⁡ (a)

多重集重写中的一步将格局 (它是无序的) 的一部分与规则的左侧相匹配, 并将其替换为规则的右侧. 因此, 在read和id的规则中, 左侧的单元从格局中消失了, 这对应于单元的释放. 由于线性定型, 这意味着在计算结束时, 只有从无参数过程的初始目的地可达的单元会在格局中保持分配状态. 换言之, 我们不需要传统的垃圾回收器.

type bool = +{'false : 1, 'true : 1}

proc dealloc_bool (d : 1) (x : bool) =
  read x {
  | 'false(u) => id d u
  | 'true(u) => read u ()
                write d ()

proc and (d : bool) (x : bool) (y : bool) =
  read x {
  | 'false(u) => cut w : 1
                    call dealloc_bool w y
                 read w ()
                 write d 'false(u)
  | 'true(u) => read y {
                | 'false(w) => read u {
                               | () => write d 'false(w)
                               }
                | 'true(w) => read u ()
                              write d 'true(w)
                }
  }

type bin = +{'b0 : bin, 'b1 : bin, 'e : 1}

第2章 定型的两个问题

让我们只看其中两条规则, 并考察实现它们时的问题. y:A ⊢ idxy :: ( x:A ) id Γ⊢ P:: ( x:A ) Δ, x:A ⊢ Q::δ Γ,Δ ⊢ cut ( x:A ) PQ ::δ cut 第一个问题在恒等规则中可见: 我们被给定了y:B⊢idxy::(x:A), 并且如果B=A的话, 我们就应该接受这个恒等是良类型的. 但是两个类型何时相等呢? 在当今的许多函数式语言中, 递归类型定义是生成性的, 因此一个类型名称只等于其自身. 但是这里我们有等价递归的定义, 因此一个类型名称等于其定义项. 在存在递归的情况下, 这就产生了判定两个类型是否相等的问题.

第二个问题以切规则为例. 每个变量都应当恰好被使用一次, 但是一些变量会出现在P中, 另一些会出现在Q中, 那么我们如何拆分结论中的上下文呢?

我们将依次处理这两个问题.

第3章 加法式算法定型

假设类型相等的问题可以解决, 以下是设计线性类型检查算法的一种方法. 因为我们不知道如何拆分上下文, 我们就直接把它传给切的两个前提. 对于进行检查的命令, 我们返回在其类型检查中实际用到的上下文. 然后我们将两者组合起来, 并且如果 (例如) 一个变量在两侧都被使用了, 就失败. 这个新的判断是Γ⊢P::(x:A)/Ξ, 其中Γ,P,x和A是输入, 而如果定型成功, Ξ是输出. Ξ包含了在P中实际用到的变量. 换言之:

如果Γ⊢P::(x:A)/Ξ, 那么Ξ⊢P::(x:A).

反过来:

如果Ξ⊢P::(x:A), 那么对于所有与Ξ不相交的Γ, 都有Γ,Ξ⊢P::(x:A)/Ξ.

于是, 切规则的第一个版本可能是 Γ⊢ P:: ( x:A ) / Ξ1 Γ, x:A ⊢ Q::δ / Ξ2 Γ⊢ cut ( x:A ) PQ ::δ / Ξ1 ; Ξ2 cut?? 其中Ξ1;Ξ2合并两个不同的上下文, 并检查它们是不相交的 (见下面的定义). 然而, 这并不完全正确. 我们还需要确保x在Q的定型中真的被使用了, 并且它没有逃逸出其作用域. 因此我们得到 Γ⊢ P:: ( x:A ) / Ξ1 Γ, x:A ⊢ Q::δ / Ξ2 Γ⊢ cut ( x:A ) PQ ::δ / Ξ1 ; ( Ξ2 ∖x ) cut 这里, Ξ2∖x从Ξ2中移除(x:A), 并且也验证了这样的x确实在Ξ2中. {译注: 原文此处写作从Ξ中移除, 应为笔误; 另外, 原文接下来的一句This means,没有写完.}

减法式定型的想法是将判断改为 ΓI ⊢ P:: ( x:A ) / ΓO 其中ΓI是可用的输入, 而ΓO是在P中没有被用到的前件. 于是切规则变为 ΓI ⊢ P:: ( x:A ) / ΓM ΓM , x:A ⊢ Q::δ / ΓO x∉ ΓO ΓI ⊢ cut ( x:A ) PQ ::δ / ΓO cut 减法式定型的正确性定理更为复杂, 尽管在某些情况下它可能提供更好的错误信息, 因为错误一般在出现时就会被立即检测到. 换言之, 通过将Γ传给切的两个前提, 我们丢失了减法式版本中存在的一些信息.

第4章 类型相等

考虑类型定义 type nat= ⊕ { zero_ :1 , succ_ :nat } type unary= ⊕ { zero_ :1 , succ_ :unary } 那么nat和unary恰好寓居着相同的大值: zero_⁡(),succ_⁡(zero_⁡()), 等等. 因此, 这两个类型应该被视为相等的. 由于其定义中的递归, 我们使用这种相等的一个余归纳定义, 允许无穷推导. 1=1 1S A1 = B1 A2 = B2 A1 ⊗ A2 = B1 ⊗ B2 ⊗S L=K Aℓ = Bℓ ( ∀ ℓ∈L ) ⊕ { ℓ: Aℓ } ℓ∈L = ⊕ { k: Bk } k∈K ⊕S

没有关于名称的显式规则, 因为我们可以隐式地将其替换为其定义项. 而这正是无穷推导的问题可能产生之处. 例如, 我们可以构造: 1=1 1S 1=1 1S ⋮ nat=unary nat=unary ⊕S nat=unary ⊕S 那么, 既然我们无法产生无穷推导, 我们如何判定类型相等呢? 关键在于产生它们的有穷表示, 即循环推导. 如果一个程序中出现了n个类型, 那么在任何分支上至多会出现n2个等式. 因此, 我们最终必然要么失败, 要么成功地以一条像1S那样的公理或者一个环来封闭推导.

对于这些规则的这种解释是在说: 无论我们尝试多久去寻找反例, 都不存在反例.

第5章 子类型

我们的等价递归定义的概念暗示了一个直接的推广. 例如, 如果我们定义 type pos= ⊕ { succ_ :nat } 那么每个类型为pos的(闭的, 大的)值也将具有类型nat. 因此, 允许 y:pos ⊢ idxy :: ( x:nat ) id 是完全没有问题的.

然而, 另一个方向是行不通的: 我们无法将一个类型为nat的小值移入一个要求其内容具有类型pos的单元. {译注: 原文此处写作call, 根据上下文应为cell.} 子类型的规则只是类型相等规则的一个小变体. 1≤1 1S A1 ≤ B1 A2 ≤ B2 A1 ⊗ A2 ≤ B1 ⊗ B2 ⊗S L⊆K Aℓ ≤ Bℓ ( ∀ ℓ∈L ) ⊕ { ℓ: Aℓ } ℓ∈L ≤ ⊕ { k: Bk } k∈K ⊕S

但是请记住, 这些规则是余归纳的, 允许无穷推导.
