SMathML Reference

This is the English translation of the Chinese version of this reference.

SMathML is still a fast-moving project, so this reference may be out of date. Where the two disagree, the implementation is authoritative.

第1章 Introduction

SMathML is not a typesetting engine; at present it delegates all typesetting work to the browser. In principle, typesetting could be delegated not only to the browser but also to other backends such as LaTeX, through a transformation or output process (in which case output is itself a kind of transformation). Its model, however, is based on the browser. That is, what it provides are means of expressing HTML and MathML. (It also takes CSS and SVG into account, but that support is far from complete and hardly usable.) Even if someone did design and implement another backend, it would be indirect, and it was never the author's intention.

The purpose of SMathML is to provide a mature way of writing mathematical content on the web. Even so, the popularity of other software and libraries such as MathJax might make SMathML seem unnecessary. The problem is that almost none of these popular choices provides the necessary means of abstraction and combination. This problem has not received much attention, because LaTeX, the de facto standard for mathematical typesetting, is already hard to praise when it comes to abstraction and combination. (Moreover, most software and libraries offer only a restricted imitation of LaTeX, which weakens abstraction and combination even further.) Nevertheless, the problem is real, and that is why the author designed and implemented SMathML.

SMathML is currently a DSL embedded in Racket. In other words, users can enjoy the whole Racket ecosystem without restriction, in sharp contrast with some other typesetting systems, such as Typst. Embedding it in other Scheme implementations may be possible, but since SMathML freely uses Racket's own keyword argument mechanism, a compatibility layer may not be easy to implement. Users could, however, choose to start afresh and change some of SMathML's own means of expression.

SMathML is based on SXML, which can be understood as a direct list representation of XML in Scheme/Lisp. SXML could perhaps also be understood as a syntax, but that view is both unnecessary and too restrictive, so we do not adopt it. The reason is that SMathML's expressive power comes from its ability to manipulate and transform SXML directly. Our SXML is not exactly the same as Oleg Kiselyov's SXML, whereas the SXML library provided by Racket follows Oleg Kiselyov's design. The difference is that in our SXML the attribute list is mandatory: when there are no attributes, an empty list is used, which makes the representation more uniform. This does make writing bare SXML more tedious. However, since many basic functions are provided, this is no problem at all in actual use of SMathML. SMathML also provides a transformation mechanism similar to Oleg Kiselyov's SXSLT, but it offers only a small part of SXSLT's functionality. For now, at least, the author considers that sufficient.

第2章 Basic Functions

This chapter is a reference for the most basic functions, which express MathML and HTML in SXML form. There is nothing surprising here; a quick skim is enough to master it completely.

第2.1节 The MathML Part

(define (Math #:attr* [attr* '()] . mathml*)
  `(math ,attr* . ,mathml*))
Let us look at this procedure first; all the remaining procedures in this chapter follow exactly the same pattern. It takes one keyword argument, the attributes, which defaults to empty. Our naming convention is that the name of the SMathML procedure corresponding to a MathML or HTML element is the element name with its first letter capitalized. That is all there is to say.

第2.1.1小节 Some Useful Supplementary Definitions

(define (MathB #:attr* [attr* '()] . mathml*)
  `(math ((display "block") . ,attr*) . ,mathml*))
(define M Math)
(define MB MathB)
(define (MBL label . exp*)
  (MB (Mtable #:attr*
              '((columnalign "left center right")
                (displaystyle "true")
                (width "100%"))
              (Mtr (Mtd (Mphantom label))
                   (apply Mtd exp*)
                   (Mtd label)))))
Here MathB sets the display attribute to block, while M and MB are abbreviations of Math and MathB, respectively. Note that the Math element has two rendering modes, inline and block, the default being inline; anyone who has used LaTeX should find this easy to understand. As for MBL, it builds on MB by adding a label to the formula.

第2.2.1小节 Some Useful Supplementary Definitions

The HTML part likewise has some useful supplementary definitions.

(define (Prelude #:title [title "index"] #:css [css '()] . body*)
  (Html
   (apply
    Head
    (Meta #:attr* '((charset "utf-8")))
    (Title title)
    (map (lambda (stylesheet)
           (Link #:attr* `((href ,stylesheet) (rel "stylesheet"))))
         (if (string? css) (list css) css)))
   (apply Body body*)))
Prelude lets users construct a web page more easily; it is a simple abstraction over the basic case.

(define (CodeB . str*)
  (Pre (apply Code str*)))
CodeB is used for code blocks. Custom attributes might be worthwhile for it as well, but I have never needed them.

第4.1节 Operators and Infix Operators

Operators are one of the basic ingredients of mathematical notation, so we provide a number of convenient tools along with definitions of many common operators.

(define ((make-op op n u) . x*)
  (cond
    ((null? x*) (n))
    ((null? (cdr x*)) (u (car x*)))
    (else
     (let iter ((x (car x*)) (x* (cdr x*)) (r '()))
       (if (null? x*)
           (apply Mrow (reverse (cons x r)))
           (iter (car x*)
                 (cdr x*)
                 (cons op (cons x r))))))))
(define (err0 id)
  (lambda ()
    (error id "")))
(define (err1 id)
  (lambda (x)
    (error id "~s" x)))
make-op defines the procedure corresponding to an operator, which accepts any number of arguments. With two or more arguments, it behaves as an infix operator. The cases of zero and one argument are left for the user to define separately. If the user wants those cases to signal an error, err0 and err1 are available.

(define (make-infix op id)
  (make-op op
    (err0 id)
    (err1 id)))
(define-syntax define-infix*
  (syntax-rules ()
    ((_ (id op) ...)
     (begin
       (define id (make-infix op 'id))
       ...))))
We also have the make-infix procedure and the define-infix* macro, which make it easy to define infix operator procedures that only accept two or more arguments.

Let us look at some examples to see how these tools are used.

(define &cm
  (make-op $cm
    (lambda () $)
    (lambda (x) x)))
The definition of &cm depends on $cm, which is defined as

That is, &cm is a procedure that separates its arguments with commas. Given a single argument, it returns that argument itself. Given no arguments, it returns the placeholder $. Note that, as a general rule, we use the $ prefix for things that are not functions, and the & prefix for the procedure that expresses the corresponding notation.

Here is another example.

    (err0 '&-)
    (lambda (x) (Mrow $- x))))

第4.2节 Big Operators

There is another special kind of operator that we use often, which might be called big operators.

(define (make-bigop op)
  (case-lambda
    ((u o e) (Mrow (Munderover op u o) e))
    ((u e) (Mrow (Munder op u) e))
    ((e) (Mrow op e))))
(define-syntax define-bigop*
  (syntax-rules ()
    ((_ (id op) ...)
     (begin
       (define id (make-bigop op))
       ...))))
make-bigop defines the procedure corresponding to a big operator, and define-bigop* is a macro for defining many big operator procedures at once.

A big operator procedure always accepts one, two or three arguments. With one argument, the big operator has no limits above or below it. With two, it has only a lower limit. With three, it has both. This matches exactly how big operators are customarily used. Note, however, that the limits of a big operator are rendered differently in inline mode and in block mode, which is in fact much the same as in LaTeX. In inline mode the limits become sub- and superscripts, while in block mode they really do appear above and below the operator. To get the block-mode style in inline mode, set the displaystyle attribute to true.

  (prod $prod)

  (Cup $Union)

  (Cap $Cap)
  (Disj $Disj)

These are the big operator procedures SMathML currently provides. Perhaps sum and prod should have been capitalized, but by now the habit is too entrenched to change.

第4.5节 Function Application

Standard prefix function application is one of the most frequently used notations in mathematics, so we provide the following procedures.

(define $af (Mo "&af;"))

  (Mrow f $af x))

  (ap f (apply @ x*)))

  (case-lambda
    ((f x) (app f x))
    ((f g . arg*) (app f (apply app* g arg*)))))

  (ap f (apply tu0 x*)))
Inserting $af is what the official documentation does, and I chose not to deviate from that standard. ap is for plain application, which is uncommon in mathematics but does occur. app is for application with the argument in parentheses, the most common form in mathematics. app* is the iterated version of app, which is occasionally very useful. appl is for applying a function of several arguments, and uses tu0.

第4.10节 Abstractions over Laws and Axioms

Part of SMathML's flexibility lies in its ability to express many higher-order abstractions. One direct application is expressing laws and axioms, such as commutativity and associativity. The current definitions are not polished enough, and readers are generally advised to define their own as needed; what follows is only meant to get the ball rolling.

(define (commute* a b)
  (&= (&i* a b) (&i* b a)))
(define (commute+ a b)
  (&= (&+ a b) (&+ b a)))
(define (commute & a b)
  (&= (& a b) (& b a)))
(define (assoc* a b c)
  (&= (&i* a (@ (&i* b c)))
      (&i* (@ (&i* a b)) c)))
(define (assoc+ a b c)
  (&= (&+ a (@ (&+ b c)))
      (&+ (@ (&+ a b)) c)))
(define (associate & a b c)
  (&= (& (@ (& a b)) c) (& a (@ (& b c)))))
(define (disL a b c)
  (&= (&i* (@ (&+ a b)) c)
      (&+ (&i* a c)
          (&i* b c))))
(define (disR a b c)
  (&= (&i* a (@ (&+ b c)))
      (&+ (&i* a b)
          (&i* a c))))
(define (distributeL a + b * c)
  (&= (* (@ (+ a b)) c)
      (+ (@ (* a c)) (@ (* b c)))))
(define (distributeR a * b + c)
  (&= (* a (@ (+ b c)))
      (+ (@ (* a b)) (@ (* a c)))))
Readers may find that they sometimes need to swap the two sides of the equation, which is one of the oversights in these procedures.

There is one more procedure that, although not yet part of SMathML, may be worth a look:

第4.11节 Derivations

Derivations are actually implemented with tables as well, but the author preferred to give them a section of their own.

(define (make-row . x*)
  (apply Mtr (map Mtd x*)))
(define (deriv x y . z*)
  (keyword-apply
   Mtable
   '(#:attr*) '(((displaystyle "true") (columnalign "right center left")))
   (cons (make-row x $= y)
         (map (lambda (z) (make-row $ $= z)) z*))))
(define (deriv0 x -> y . z*)
  (keyword-apply
   Mtable
   '(#:attr*) '(((displaystyle "true") (columnalign "right center left")))
   (cons (make-row x -> y)
         (map2 (lambda (-> w) (make-row $ -> w)) z*))))
deriv is for derivations whose steps are all joined by equals signs, while deriv0 lets the user choose the connectives. Originally both definitions were rather complicated, chiefly because columnalign used to be set cell by cell; only later did the author realize that this was unnecessary.

Building on set-attr*, introduced later, SMathML also provides some derived procedures.

(define-syntax-rule (eqn* (x ...) ...)
  (MB (set-attr*
       (&Table (x ...) ...)
       'columnalign "right center left"
       'displaystyle "true")))
eqn* aligns things the same way as deriv, but allows rows other than the first to have something on the left as well.
(define (deriv^ x . y*)
  (set-attr*
   (apply
    Mtable
    (Mtr (Mtd $) (Mtd x))
    (map (lambda (y)
           (Mtr (Mtd $=) (Mtd y)))
         y*))
   'displaystyle "true"
   'columnalign "center left"))
(define (deriv^0 x . y*)
  (set-attr*
   (apply
    Mtable
    (Mtr (Mtd $) (Mtd x))
    (map2 (lambda (= y)
            (Mtr (Mtd =) (Mtd y)))
          y*))
   'displaystyle "true"
   'columnalign "center left"))
deriv^ and deriv^0 are similar to deriv and deriv0 respectively; the difference is that what used to be on the left of the first row is folded over to the right. For extremely long formulas, these two procedures are indispensable.

第5章 Transformations

Transformations are the core of SMathML; without them many abstractions would be hard to express.

第5.1节 The General Transformation T

Let us start with the code of T.

(define (T style*)
  (define default-handler
    (let ((default-binding (assoc '(default) style*)))
      (match default-binding
        (`((default) *preorder* ,handler) handler)
        (`((default) ,handler)
         (lambda (tag attr* . xml*)
           (apply handler tag attr* (map transform xml*))))
        (else
         (lambda (tag attr* . xml*)
           `(,tag ,attr* . ,(map transform xml*)))))))
  (define text-handler
    (let ((text-binding (assoc '(text) style*)))
      (if text-binding
          (cadr text-binding)
          identity)))
  (define Style*
    (map
     (lambda (binding)
       (match binding
         (`(,tag *preorder* ,handler)
          (cons tag handler))
         (`(,tag ,handler)
          (cons tag
                (lambda (tag attr* . xml*)
                  (apply handler tag attr*
                         (map transform xml*)))))))
     (filter (lambda (style) (symbol? (car style)))
             style*)))
  (define (transform xml)
    (match xml
      (`(,tag ,attr* . ,xml*)
       (let ((binding (assq tag Style*)))
         (if binding
             (apply (cdr binding) tag attr* xml*)
             (apply default-handler tag attr* xml*))))
      (str (text-handler str))))
  transform)

第5.2节 Modifying Attributes

SMathML provides two procedures for modifying attributes: attr*-set and set-attr*. In fact, set-attr* is built on attr*-set.

(define (attr*-set attr* . xv*)
  (define (s a* x v)
    (if (eq? v #f)
        a*
        (let s ((a* a*) (x x) (v v))
          (cond ((null? a*)
                 (list (list x v)))
                ((eq? (caar a*) x)
                 (cons (list x v) (cdr a*)))
                (else
                 (cons (car a*)
                       (s (cdr a*) x v)))))))
  (if (null? xv*)
      attr*
      (let iter ((x (car xv*))
                 (v (cadr xv*))
                 (xv* (cddr xv*))
                 (a* attr*))
        (if (null? xv*)
            (s a* x v)
            (iter (car xv*) (cadr xv*) (cddr xv*)
                  (s a* x v))))))
attr*-set modifies the association list representing the attributes, and can take several attributes to modify at once. The procedure is currently not very efficient; a simple append might well be the better practical choice. That would subtly change the semantics, though, since currently a modification appearing later can override an earlier one. Then again, in my own use of SMathML I seem never to have done that. Of course, the current implementation has a merit of its own: it produces the most compact attribute lists.
(define (set-attr* xml . xv*)

第5.3节 Tm: An Auxiliary Transformation for Mathematical Content

Tm is a core transformation procedure; almost every page of the author's blog uses Tm. In fact, whenever a page contains mathematical content, it should use Tm; this is the recommended practice.

Tm fixes some of the awkwardness of using SMathML. For example, without Tm, even a MathML element meant to be inline would have to be wrapped in Math or M, which is clearly unreasonable. Merely adding Math is easy to automate: one only needs to detect MathML elements left bare. But expressions already wrapped in a MathML root element must be left alone, and so must their attributes; otherwise, for instance, switching between inline and block mode would break. Tm also smooths over some other awkward points. For example, using text inside MathML used to require adding Mtext by hand, which Tm now automates completely. Tm also transforms some other constants that would otherwise be invalid, for example wrapping integers in Mn. Moreover, for a bare integer, Tm does not forget to add Math. Symbols and fractions are also handled by Tm as intuitively as possible.

第6章 Automatic Numbering and Cross-References

Automatic numbering and cross-referencing are essential in practice. SMathML now has preliminary support for them, though it is rather cumbersome to use.

The rough idea is as follows. We use special vector tags whose fields are, naturally, mutable. First we accumulate information in a linear traversal, constructing the corresponding headings and entries, together with their citation forms, along the way. We also build an association list from strings to citation forms. Then a second traversal replaces references made by strings with the corresponding citation forms.

This mechanism is not elegant, but at least it is serviceable; it will quite likely be rewritten substantially in the future.

第6.1节 Implementation

    (if (= i level)

        (else (aux henv len))))

           (printf "/>"))
         (begin
           (printf "<~s" tag)
           (Attr* attr*)
           (printf ">")
           (for-each Xml xml*)
           (printf "</~s>" tag))))
    ((? string? str)
     (printf "~a" str))))

第7.3节 Outputting to Files

Of course, outputting alone is not enough; we also provide some auxiliary procedures for outputting to files.

(define (size x)
  (cond ((pair? x) (+ (size (car x)) (size (cdr x))))
        ((null? x) 0)
        ((string? x) (string-length x))
        (else 1)))
(define replace? (make-parameter #f))
(define compute-size? (make-parameter #f))
(define ((emit proc) exp path)
  (define (emit-file)
    (when (compute-size?)
      (printf "size of [~a]: ~a\n" path (size exp)))
    (with-output-to-file path
      (lambda () (proc exp))
      #:exists 'replace))
  (if (file-exists? path)
      (if (replace?)
          (emit-file)
          (printf "~s exists, emit cancelled\n" path))
      (emit-file)))
(define ((emit-thunk proc) thunk path)
  (define (emit-file)
    (define exp (thunk))
    (when (compute-size?)
      (printf "size of [~a]: ~a\n" path (size exp)))
    (with-output-to-file path
      (lambda () (proc exp))
      #:exists 'replace))
  (if (file-exists? path)
      (if (replace?)
          (emit-file)
          (printf "~s exists, emit cancelled\n" path))
      (emit-file)))
(define ((emit-promise proc) promise path)
  (define (emit-file)
    (define exp (force promise))
    (when (compute-size?)
      (printf "size of [~a]: ~a\n" path (size exp)))
    (with-output-to-file path
      (lambda () (proc exp))
      #:exists 'replace))
  (if (file-exists? path)
      (if (replace?)
          (emit-file)
          (printf "~s exists, emit cancelled\n" path))
      (emit-file)))
We could in fact merge emit, emit-thunk and emit-promise into a single procedure, but the current design may reduce the chance of mistakes. These procedures do just what their names suggest: emit simply outputs to a file; emit-thunk outputs a thunk (a function of no arguments), which therefore has to be called first; emit-promise outputs a promise, which therefore has to be forced first.

We provide both emit-thunk and emit-promise because a promise caches the result of its computation. Sometimes, however, we may want to run benchmarks, and then a plain thunk suits our needs better. Either way, both procedures can save some work when many files need to be output. (This is of course not automated at all; the user has to decide by hand.)

Based on emit and emit-thunk, we provide the following procedures:

  (emit-promise Xml))

We really should also provide emitXml-promise and emitCss-promise, but the author forgot them, which was a mistake. They will probably be added in the future.

第8.9节 General Folds over SXML

The folds given here are, in a sense, generalizations of the list operations fold-left and fold-right to SXML.

(define (fold-left proc init lst)
  (if (null? lst)
      init
      (fold-left proc (proc init (car lst)) (cdr lst))))
(define (fold-right proc init lst)
  (if (null? lst)
      init
      (proc (car lst)
            (fold-right proc init (cdr lst)))))
(define (Fold fdown fup fhere seed xml)
  (match xml
    (`(,tag ,attr* . ,xml*)
     (define entering
       (fdown seed tag attr* xml*))
     (define enjoying
       (fold-left
        (lambda (seed xml)
          (Fold fdown fup fhere seed xml))
        entering xml*))
     (fup seed enjoying tag attr* xml*))
    (else (fhere seed xml))))
(define (Fold* fdown fup fhere seed xml)
  (match xml
    (`(,tag ,attr* . ,xml*)
     (define-values (entering new*)
       (fdown seed tag attr* xml*))
     (define enjoying
       (fold-left
        (lambda (seed xml)
          (Fold* fdown fup fhere seed xml))
        entering new*))
     (fup seed enjoying tag attr* xml*))
    (else (fhere seed xml))))
The idea of Fold and Fold* comes from the context of SSAX, but they operate directly on SXML rather than on text that has not yet been parsed.

第8.10节 HTML Pretty-Printing

All the code in this part was generated by an LLM and has not been reviewed by a human with full understanding. Use it with caution, and never use it in any production environment. That said, the XML provided here is arguably more conservative than most HTML pretty-printers. In principle, however, the correct indentation behavior of HTML depends on its CSS, so our pretty-printer cannot be completely correct.

Based on Fold from the previous section, we provide an HTML pretty-printer here. You can of course also use it to pretty-print XML, and we provide the parameter inline-tags to control indentation.

(struct state (idt ctx) #:transparent)
(define inline-tags
  (make-parameter
   (seteq
    'pre 'textarea 'script 'style
    'b 'i 'em 'strong 'span 'a 'u 's
    'code 'kbd 'samp 'var
    'abbr 'cite 'q 'sub 'sup 'small 'mark
    'del 'ins 'time 'wbr 'br
    'bdi 'bdo 'data 'ruby 'rt 'rp
    'img 'input 'output 'select 'button 'label
    'mi 'mn 'mo 'ms 'mtext 'mspace 'annotation
    'tspan 'textPath
    'math 'svg)))
(define (inline? tag)
  (set-member? (inline-tags) tag))
(define (inline-element? tag attr*)
  (and (inline? tag)
       (not (and (eq? tag 'math)
                 (for/or ([a (in-list attr*)])
                   (and (eq? (car a) 'display)
                        (equal? (cadr a) "block")))))
       (not (and (eq? tag 'svg)
                 (for/or ([a (in-list attr*)])
                   (and (eq? (car a) 'style)
                        (string-contains? (cadr a) "display: block")))))))
(define (XML xml)
  (define (fdown seed tag attr* xml*)
    (define idt (state-idt seed))
    (define ctx (state-ctx seed))
    (define child-inline?
      (inline-element? tag attr*))
    (cond
      [(eq? ctx 'inline)
       (void)]
      [(eq? ctx 'block-nl)
       (display (make-string idt #\space))]
      [else
       (unless child-inline?
         (newline)
         (display (make-string idt #\space)))])
    (printf "<~a" tag)
    (for ([a (in-list attr*)])
      (printf " ~a=~s" (car a) (cadr a)))
    (cond
      [(null? xml*)
       (display "/>")
       (when (and (not (eq? ctx 'inline)) (not child-inline?))
         (newline))
       seed]
      [else
       (display ">")
       (cond
         [(eq? ctx 'inline) (state idt 'inline)]
         [child-inline?     (state idt 'inline)]
         [else              (state (+ idt 2) 'block)])]))
  (define (fup seed enjoying tag attr* xml*)
    (when (pair? xml*)
      (when (eq? (state-ctx enjoying) 'block-nl)
        (display (make-string (state-idt seed) #\space)))
      (printf "</~a>" tag)
      (when (and (not (eq? (state-ctx seed) 'inline))
                 (not (inline-element? tag attr*)))
        (newline)))
    (cond
      [(eq? (state-ctx seed) 'inline) seed]
      [(inline-element? tag attr*)
       (state (state-idt seed) 'mixed)]
      [else
       (state (state-idt seed) 'block-nl)]))
  (define (fhere seed xml)
    (define ctx (state-ctx seed))
    (when (eq? ctx 'block-nl)
      (display (make-string (state-idt seed) #\space)))
    (display xml)
    (if (eq? ctx 'inline)
        seed
        (state (state-idt seed) 'mixed)))
  (Fold fdown fup fhere (state 0 'block-nl) xml))
The inline-element? in this code is mainly there to fit how SMathML is used. For general HTML and XML pretty-printing, it can be dropped in favor of testing with inline?.

Here we present an EDSL built on SMathML that checks a proof and then generates the corresponding natural deduction tree. This example would probably be rather hard to implement in other typesetting systems.

第11章 Comparison with Other Tools

The items chosen for comparison here overlap with SMathML either in functionality or in design decisions. I had not heard of many of them before designing and implementing SMathML; I only learned of them recently, with the help of LLMs.

第11.1节 Oleg Kiselyov's SXML

SXML is not just SXML itself; it also comprises a family of tools for processing SXML, including SSAX, SXPath and SXSLT. The names SXML, SSAX, SXPath and SXSLT suggest their connection with XML, SAX, XPath and XSLT. This does not mean, however, that these S-prefixed tools work merely at the level of syntax, that is, that they merely translate the conventional syntax into the parenthesized syntax of Lisp-family languages.

第11.2节 DSSSL

DSSSL is similar in function to XSLT, but was originally designed for SGML, though it later came to support XML as well. What is most distinctive about DSSSL is that it is based on Scheme.

第11.3节 LAML

LAML and SMathML share many ideas, yet they also differ in many details. For example, LAML lets symbols serve as attribute names, with the strings that follow them serving as attribute values. This (concrete) syntax might also be adopted in ports of SMathML to other Scheme dialects and implementations. LAML also chooses to insert implicit spaces between pieces of content. These differences open a wide gap between LAML's surface syntax and the underlying syntax tree, which I personally do not like.
